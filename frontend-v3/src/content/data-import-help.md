# Импорт данных — справка

## Назначение

Сервисная операция позволяет **массово создать или обновить** записи реестров из файла Excel по шаблону системы. Справочники (раздел «Справочники») через этот импорт **не** загружаются — они используются как источник допустимых значений.

## Типовой сценарий

1. Откройте **Настройки → Сервисные операции → Данные → Импорт данных**.
2. Выберите **реестр** (веб-ресурсы, системы, технологии, принципы, архитектурный долг, принципиальные ADR, орг. единицы, заинтересованные лица, бизнес-сервисы, бизнес-функции).
3. Нажмите **«Скачать шаблон»** — получите файл с листом «Данные», листами справочников и выпадающими списками (проверка данных Excel).
4. Либо нажмите **«Скачать текущий реестр (экспорт)»** — тот же формат, но уже с существующими строками (удобно для массового обновления).
5. Заполните или поправьте строки на листе **«Данные»**.
6. Сохраните файл и загрузите его на форме импорта.
7. При необходимости выберите: что делать, если запись уже есть; состав протокола.
8. Нажмите **«Проверить»** (без сохранения в БД) или **«Загрузить»** (частичная запись: удачные строки сохраняются, ошибочные — в протоколе).
9. Скачайте **протокол** — исходные колонки плюс статус и текст ошибки по строкам.

## Что заполнять

- Заполняйте **только те столбцы, которые соответствуют полям карточки (формы) реестра**. Заголовки в файле совпадают с подписями на форме; в скобках указано техническое имя поля.
- Столбец **ID** и столбцы с сырыми идентификаторами (справа) **не заполняйте** при ручном вводе — система их не использует при записи. В экспорте они могут быть заполнены для справки.
- Значения ссылочных полей (статус, категория, информационная система и т.п.) берите **из листов справочников** файла или выбирайте из **выпадающего списка** в ячейке. Имя должно **точно совпадать** со справочником.
- Для реестров с автокодом (веб-ресурсы, архитектурный долг, принципиальные ADR): для **создания** оставьте код пустым; для **обновления** укажите существующий код.
- Для каталога ИС: код **обязателен** (новый код = создание, существующий = обновление).
- Для реестров без кода (принципы, технологии, орг. единицы и др.): ключ — **наименование**; совпавшее имя обновляет запись, новое — создаёт.
- По умолчанию при обновлении меняются **только непустые** ячейки строки (пустая ячейка не затирает значение в БД).

## Не входит в импорт

- Прикладные ADR (`applied`) — вложенные инкременты/системы/интеграции.
- Связи метамодели на вкладках (долг ↔ объекты, стек технологий ИС).
- Интеграционные потоки (отдельный реестр без типа сущности импорта).
- Справочники (партнёры, сотрудники, статусы и т.п.) — ведутся в разделе «Справочники».

## Важно

- Импорт идёт через ту же логику, что сохранение карточки: обязательные поля и проверки формы действуют и здесь.
- «Проверить» не сохраняет данные в реестре (откат транзакции); возможны «дыры» в автонумерации кодов — это нормально.
- Иерархии (орг. единицы, бизнес-функции, модули ИС): сначала загрузите родителей, затем дочерние строки.
- Если после экспорта правите файл вручную, не удаляйте листы справочников — иначе пропадёт удобный выбор из списка (при импорте имена всё равно сверяются с данными в системе).
