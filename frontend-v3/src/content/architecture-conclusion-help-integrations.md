## Взаимодействие между системами

В данном разделе описывается взаимодействие между системами, задействованными в рамках реализации архитектурного заключения. Указываются источники данных, получатели, объекты обмена, способ взаимодействия и текущий статус интеграции.

### Правила заполнения полей

| Поле                                                     | Описание                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Система-источник**                                     | Указывается наименование системы, из которой исходит информация или данные. Название выбирается из списка систем, добавленных в блок «Системы» данного решения.                                                                                                                                                                                                                              |
| **Система-получатель**                                   | Указывается наименование системы, которая принимает информацию или данные. Название выбирается из списка систем, добавленных в блок «Системы» данного решения.                                                                                                                                                                                                                               |
| **Наименование**                                         | Краткое наименование передаваемых сущностей                                                                                                                                                                                                                                                                                                                                                  |
| **Описание**                                             | Краткое описание механизма интеграции: REST API, файловый обмен, очередь сообщений (Kafka, RabbitMQ), база данных и т.д. Указываются ключевые технические детали и логика передачи данных.                                                                                                                                                                                                   |
| **Статус интеграции в рамках архитектурного заключения** | Возможные значения: 1) **Создается** — создаётся в рамках данного архитектурного заключения; 2) **Модифицируется** — модифицируется в рамках данного архитектурного заключения; 3) **Используется** — используется (без изменений) в рамках данного архитектурного заключения; 4) **Выводится из эксплуатации** — в рамках данного архитектурного заключения будет выведена из эксплуатации. |

### Пример таблицы

| Система-источник | Система-получатель | Наименование  | Описание способа взаимодействия                                                                                 | Статус         |
| ---------------- | ------------------ | ------------- | --------------------------------------------------------------------------------------------------------------- | -------------- |
| СУД              | ERP                | Права доступа | Интеграция через REST API с использованием OAuth 2.0. Обновления прав передаются по событиям в реальном времени | Создается      |
| ERP              | BI-платформа       | Сотрудники    | Выгрузка данных выполняется ежедневно через ETL-процесс с использованием Apache NiFi                            | Модифицируется |
| 1С:ЗУП           | СУД                | Сотрудники    | Файловый обмен (CSV) с последующей загрузкой в СУД по расписанию                                                | Используется   |

Данная структура позволяет однозначно описать все межсистемные взаимодействия и их состояние.
