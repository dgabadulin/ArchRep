# infra/prod

Prod-скрипты деплоя и compose-файлы.

- `deploy.bat` — основной SSH-деплой из Windows.
- `linux_deploy.bat` — альтернативный вариант деплоя.
- `docker-compose.yml` — compose-вариант для API (опционально).

Запуск из корня репозитория:

```cmd
infra\prod\deploy.bat
```

## Адреса после деплоя

Контейнер публикует порт `3000` (`-p 3000:3000`), но доступность этого порта с рабочей машины определяет сеть, а не приложение:

| Что | Адрес | Комментарий |
|---|---|---|
| Приложение на сервере | `http://127.0.0.1:3000` | проверяется скриптом перед «Деплой завершён» |
| Внешний адрес (nginx/443) | `DEPLOY_PUBLIC_URL` (например `https://isar.st.tech`) | выводится в конце, если переменная задана |
| Прямой порт с ПК | `http://<target>:3000` | часто закрыт ACL — тогда только через туннель |
| SSH-туннель | `ssh -L 3000:127.0.0.1:3000 <user>@<jump>@<target>` | затем `http://127.0.0.1:3000` |

Если `:3000` не открывается, а `/api/health` на сервере отвечает `200` — деплой прошёл, дело в сетевом фильтре между вами и хостом (типично разрешены только 22/443).
