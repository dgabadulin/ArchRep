# Дизайн: параметры системы (Настройки → Параметры)

Единый механизм хранения и редактирования параметров, влияющих на поведение системы: подключения к внешним сервисам (например Keycloak), лимиты, флаги функций, списки допустимых значений и т.д. Доступ: **Меню → Настройки → Параметры**.

## Модель параметра

| Поле | Описание | Обязательность |
|------|----------|----------------|
| **Имя (код)** | Уникальный идентификатор параметра в системе, например `SEC_KEYCLOAK_ENABLED`, `AR_SESSION_TIMEOUT_MIN`, `AR_ALLOWED_ORIGINS`. Используется в коде и при подстановке из окружения. Префиксы: **`SEC_`** — SSO/безопасность, **`AR_`** — прочее. **Имена — КАПС**, слова через `_`. | Обязательно |
| **Описание** | Человекочитаемое пояснение: зачем параметр, на что влияет. Показывается в форме редактирования и в подсказках. | Желательно |
| **Значение** | Текущее значение. Может быть одно или несколько (см. ниже). Тип зависит от параметра: строка, число, булево, JSON, список. | Обязательно (или «пусто» + default в коде) |

## Одно значение vs несколько значений

- **Одно значение**  
  Классический параметр: одно поле.  
  Примеры: `SEC_KEYCLOAK_LOGIN_MODE`, `AR_PAGE_SIZE_DEFAULT`, `AR_FEATURE_NEW_UI`.

- **Несколько значений**  
  Один параметр — список (массив) значений.  
  Варианты представления:
  - Список строк (например разрешённые origins).
  - Именованные поля в рамках одного параметра (JSON-объект) либо группа параметров с общим префиксом.

Рекомендация для SSO: отдельные параметры с префиксом **`SEC_KEYCLOAK_*`** (см. таблицу и `access-control-design.md` §3.1); `client_secret` — только env. Прочие структурированные параметры — JSON или группа с префиксом `AR_`.

## Примеры параметров

| Имя | Описание | Значение (пример) | Тип |
|-----|----------|-------------------|-----|
| `SEC_KEYCLOAK_ENABLED` | Включить вход через Keycloak/OIDC (`true`) или только локальный login / без SSO (`false`). См. `access-control-design.md` §3.1 фаза B. | `true` / `false` | булево |
| `SEC_KEYCLOAK_LOGIN_MODE` | Режим UI SSO: `button` (кнопка), `auto` (сразу redirect), `silent` (тихий SSO, иначе форма логина). | `button` | строка (enum) |
| `SEC_KEYCLOAK_ISSUER` | OIDC issuer (база для discovery), напр. `https://sso.example.com/realms/common`. Secret и client_id — **только env**, не в БД. | URL | строка |
| `AR_SESSION_TIMEOUT_MIN` | Таймаут сессии в минутах. Используется при проверке активности пользователя. | `30` | число |
| `AR_ALLOWED_ORIGINS` | Список разрешённых CORS origins для API. Влияет на запросы с фронтенда. | `["https://app.example.com", "http://localhost:5173"]` | список строк |
| `AR_GRAPH_DEFAULT_LAYOUT` | Раскладка графа по умолчанию при построении: star, grid, ring. | `star` | строка (из списка) |
| `AR_MAX_GRAPH_NODES` | Максимальное число узлов на графе; при превышении предупреждение или ограничение. | `200` | число |

Где что для Keycloak (env vs параметр vs discovery) — таблица в **`access-control-design.md` §3.1**, блок «Где фиксируются константы для работы с KC».

## Размещение данных

- **Приоритет (от высшего к низшему):**  
  1) переменные окружения (для деплоя и секретов);  
  2) параметры из БД (настраиваются через «Настройки → Параметры»);  
  3) значения по умолчанию в коде/конфиге приложения.

- Параметры в БД удобно хранить в таблице вида: `code` (уникальный), `description`, `value` (текст или JSON), `value_type`, `group`, `is_secret`, `read_only`, `updated_at`. Для списков — либо JSON в `value`, либо отдельная таблица «параметр — элемент списка».

- Секреты (пароли, client_secret) предпочтительно задавать только через переменные окружения; в БД хранить только признак «значение взято из окружения» без самого значения.

## Поведение формы «Настройки → Параметры»

1. **Список параметров** — таблица или карточки: имя, группа, краткое описание, текущее значение (для секретов — «********» или «задан из окружения»), признак «только чтение».
2. **Фильтр/поиск** — по имени, группе, описанию.
3. **Редактирование** — по клику на параметр или «Изменить»:
   - поле имени (если разрешено создание новых параметров) или только отображение;
   - описание (многострочное);
   - тип значения и соответствующее поле ввода: текст, число, чекбокс, JSON-редактор, динамический список строк (добавить/удалить строку);
   - для параметра-объекта — подформа с полями; для SSO (`SEC_KEYCLOAK_*`) секрет клиента не редактировать в UI — только env.
4. **Валидация** — по типу (число, JSON), обязательность, при необходимости — формат URL, перечисление допустимых значений.
5. **Сохранение** — запись в БД; перезагрузка приложения или фоновое подхватывание новых значений (в зависимости от выбранной архитектуры).

## Итоговая структура параметра (концептуально)

- **Имя (код)** — уникальное, например `SEC_KEYCLOAK_ENABLED`.
- **Описание** — текст для пользователя.
- **Значение** — одно (строка/число/булево/JSON) или список (массив строк или набор именованных полей).
- Дополнительно в метаданных: тип значения, группа, секретность, только чтение, источник (БД / env).

Такая форма позволяет задавать и флаги/issuer SSO, и любые другие параметры системы (лимиты, флаги, списки), через единое меню «Настройки → Параметры».
