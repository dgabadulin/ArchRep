# Универсальная форма настроечных параметров системы

## Назначение

Единый механизм хранения и редактирования параметров, влияющих на поведение системы: подключения к внешним сервисам (например Keycloak), лимиты, флаги функций, списки допустимых значений и т.д. Доступ: **Меню → Настройки → Параметры**.

---

## Атрибуты параметра

| Атрибут | Описание | Обязательность |
|--------|----------|----------------|
| **Имя (код)** | Уникальный идентификатор параметра в системе, например `AR_Keycloak_config`, `AR_Session_Timeout_Min`, `AR_Allowed_Origins`. Используется в коде и при подстановке из окружения. Рекомендуется префикс (например `AR_`) и snake_case. | Обязательно |
| **Описание** | Текст: где и как параметр используется, на что влияет, примеры. Отображается в форме как подсказка/справка. | Рекомендуется |
| **Значение** | Одно значение (строка, число, JSON) или список значений — в зависимости от типа параметра. | Обязательно |
| **Тип значения** | Один из: строка, число, булево, JSON-объект, список строк (и т.п.). Определяет валидацию и способ ввода в UI. | Обязательно |
| **Группа** | Опциональная группировка в UI (например «Аутентификация», «Интеграции», «Граф/Аналитика»). | Опционально |
| **Секретность** | Признак «секретный» (пароль, ключ): в UI при редактировании маскировать значение, в логах не выводить. | Опционально |
| **Только чтение** | Параметр задаётся только из окружения/конфига и в UI не редактируется (только просмотр или скрытие). | Опционально |

---

## Одно значение и несколько значений

- **Одно значение**  
  Один параметр — одно поле: строка, число, флаг, JSON.  
  Примеры: `AR_Keycloak_Realm`, `AR_Page_Size_Default`, `AR_Feature_New_UI`.

- **Несколько значений**  
  Один параметр — список (массив) значений.  
  Варианты представления:
  - Список строк (например разрешённые origins, списки кодов).
  - Именованные поля в рамках одного параметра (например конфиг Keycloak как один параметр с полями: `url`, `realm`, `client_id`, `client_secret` — т.е. одно «значение» в виде JSON-объекта).

Рекомендация: параметры с **структурированной конфигурацией** (как Keycloak) хранить как один параметр с типом «объект» (JSON) или как группу отдельных параметров с общим префиксом (`AR_Keycloak_Url`, `AR_Keycloak_Realm`, …). В форме это может быть одна секция «Keycloak» с полями внутри.

---

## Примеры параметров

| Имя | Описание | Значение (пример) | Тип |
|-----|----------|-------------------|-----|
| `AR_Keycloak_config` | Параметры подключения к Keycloak: URL, realm, client id/secret. Используются в middleware аутентификации. | `{"url":"https://...", "realm":"...", "client_id":"...", "client_secret":"..."}` или набор отдельных полей | объект / группа полей |
| `AR_Keycloak_Enabled` | Включить аутентификацию через Keycloak (true) или работу без SSO (false). | `true` / `false` | булево |
| `AR_Session_Timeout_Min` | Таймаут сессии в минутах. Используется при проверке активности пользователя. | `30` | число |
| `AR_Allowed_Origins` | Список разрешённых CORS origins для API. Влияет на запросы с фронтенда. | `["https://app.example.com", "http://localhost:5173"]` | список строк |
| `AR_Graph_Default_Layout` | Раскладка графа по умолчанию при построении: star, grid, ring. | `star` | строка (из списка) |
| `AR_Max_Graph_Nodes` | Максимальное число узлов на графе; при превышении предупреждение или ограничение. | `200` | число |

## Размещение данных

- **Приоритет (от высшего к низшему):**  
  1) переменные окружения (для деплоя и секретов);  
  2) параметры из БД (настраиваются через «Настройки → Параметры»);  
  3) значения по умолчанию в коде/конфиге приложения.

- Параметры в БД удобно хранить в таблице вида: `code` (уникальный), `description`, `value` (текст или JSON), `value_type`, `group`, `is_secret`, `read_only`, `updated_at`. Для списков — либо JSON в `value`, либо отдельная таблица «параметр — элемент списка».

- Секреты (пароли, client_secret) предпочтительно задавать только через переменные окружения; в БД хранить только признак «значение взято из окружения» без самого значения.

## Поведение формы «Настройки → Параметры»

1. **Список параметров** — таблица или карточки: имя, группа, краткое описание, текущее значение (для секретов — «********» или «задан из окружения»), признак «только чтение».
2. **Фильтр/поиск** — по имени, группе, описанию.
3. **Редактирование** — по клику на параметр или «Изменить»:
   - поле имени (если разрешено создание новых параметров) или только отображение;
   - описание (многострочное);
   - тип значения и соответствующее поле ввода: текст, число, чекбокс, JSON-редактор, динамический список строк (добавить/удалить строку);
   - для параметра-объекта (например Keycloak) — подформа с полями (url, realm, client_id, client_secret и т.д.) с возможностью отметить «секрет» и «взять из env».
4. **Валидация** — по типу (число, JSON), обязательность, при необходимости — формат URL, перечисление допустимых значений.
5. **Сохранение** — запись в БД; перезагрузка приложения или фоновое подхватывание новых значений (в зависимости от выбранной архитектуры).

---

## Итоговая структура параметра (концептуально)

- **Имя (код)** — уникальное, например `AR_Keycloak_config`.
- **Описание** — где и как используется.
- **Значение** — одно (строка/число/булево/JSON) или список значений (массив строк и т.п.).
- **Тип** — строка, число, булево, объект (JSON), список строк.
- **Группа** — для отображения в UI.
- **Секретность** и **только чтение** — опционально.

Такая форма позволяет задавать и конфигурацию подключения к Keycloak, и любые другие параметры системы (лимиты, флаги, списки), с одним или несколькими значениями, через единое меню «Настройки → Параметры».
