# Чеклист: подключить подключаемый модуль

Короткая версия. Подробности и диагностика — `docs/modules-admin-guide.md`.

Обозначения:
- `<code>` — код модуля от поставщика (для DrawIO Pro — `drawio-pro`);
- `<version>` — версия модуля от поставщика (для DrawIO Pro — `0.1.0`);
- `<BASE_URL>` — адрес вашего стенда (например `https://isar.example.ru` или `http://10.0.0.5:3000`).

**Совсем коротко:** модуль в `modules\<code>` → три строки в env → ключ у поставщика →
`npm run build:v3` → перезапуск API → `npm run modules:status` = «проблем нет» →
кнопка на форме заключения.

---

## 0. Предусловия (до начала)

- [ ] Ядро развёрнуто штатным деплоем. Таблица `archrep.isar_modules` создаётся **деплоем ядра**
      (миграция входит в его состав) — отдельно для установки модуля её запускать не нужно.

      Проверка (только чтобы убедиться, что ядро актуально):
      ```sql
      select to_regclass('archrep.isar_modules');   -- имя таблицы, не NULL
      ```
      Если `NULL` — ядро на старом релизе: сначала обновите ядро, это не задача установки модуля.

- [ ] Запишите версию ядра: `package.json` → `version` (сейчас `1.0.0`).
- [ ] Запросите у поставщика: артефакт модуля (zip или доступ к registry), `requiresCore`,
      `version` и публичный ключ лицензии.
- [ ] Сверьте: `requiresCore` (например `>=1.0`) включает версию ядра. Если нет — **стоп**.

---

## 1. Положите модуль в проект

- [ ] **Вариант А (zip/файл от поставщика):** распакуйте в папку

```
modules\<code>\          для DrawIO Pro:  modules\drawio-pro\
```

Внутри должны появиться `manifest.json` (или `module.json`), `index.js`, папка `frontend\`.

- [ ] **Вариант Б (npm-пакет):** возьмите координаты у поставщика — имя пакета и версию
      (для DrawIO Pro: `@isar/drawio-pro@0.1.0`; версия также указана в `package.json` модуля).
      Если registry приватный, поставщик даёт `.npmrc` с токеном — он нужен **только на машине сборки**:

```bash
npm i @isar/drawio-pro@0.1.0
```

- [ ] **Если разворачиваете в Docker:** модуль должен быть на месте **до** сборки образа
      (`infra/common/dockerfile` копирует `modules/` и в сборку фронта, и в контейнер).

**Проверка**

```bash
npm run modules:status
```

Должны появиться строки `Пакет: ...` и `Манифест: module.json | legacy manifest.json`.

---

## 2. Откройте env-файл и допишите три строки

- [ ] Откройте файл окружения вашего стенда:
      `.env.development` (локально) · `infra\demo\env.demo` (демо-контейнер) · `.env.production` (прод).

- [ ] Допишите:

```env
# 1) уникальный идентификатор ЭТОЙ инсталляции (см. примечание ниже)
SYS_INSTANCE_ID=<уникальный id>
# 2) включаем модуль: <code> — код модуля; для DrawIO Pro: drawio-pro
ENABLED_MODULES=<code>
# 3) публичный ключ проверки лицензии (пришлёт поставщик вместе с ключом)
SYS_MODULE_LICENSE_PUBLIC_KEY=<публичный ключ>
```

Идентификатор можно сгенерировать командой:

```bash
npm run modules:status -- --new-instance-id
# → SYS_INSTANCE_ID=8f14e45f-...   (скопируйте строку в env)
```

**Проверка**

```bash
npm run modules:status
```

Ожидаемо: `instance_id: <ваш id>`, `enabled: true (источник: env)`.

> **Про `instance_id`.** Он «самообъявленный»: технически ничто не мешает скопировать его вместе
> с ключом на второй сервер, и лицензия там заработает — проверка офлайн. Смысл идентификатора —
> исключить случайное совпадение (например `localhost:archrep` на двух машинах) и сделать
> копирование осознанным нарушением. Полностью это закрывается только онлайн-активацией,
> которая противоречит решению «проверка офлайн» (`docs/modules-contract.md` §16.3).

---

## 3. Запросите ключ у поставщика

- [ ] Отправьте письмо:

```
Продукт: <code>                    (для DrawIO Pro: drawio-pro)
Стенд: <демо / прод / название>
instance_id: <значение из строки «instance_id:» вывода modules:status>
Редакция / срок: <что купили>
```

- [ ] Получите ключ — строку из двух частей через точку: `xxxxx.yyyyy`.

**Проверка:** ключ сохранён; в переписку с широким кругом лиц его не вставляйте.

---

## 4. Пропишите ключ в тот же env-файл

- [ ] Добавьте строку:

```env
SYS_MODULE_drawio_pro_LICENSE=<ключ из письма>
```

Имя переменной строится по правилу `SYS_MODULE_<code>_LICENSE`, где **код модуля подставляется
буквально, строчными буквами**, а дефисы заменяются на `_`:
`drawio-pro` → `SYS_MODULE_drawio_pro_LICENSE`.

> Почему `drawio_pro`, а не `DRAWIO_PRO`: это правило контракта (`docs/modules-contract.md` §14
> «Соглашения») — `<code>` вставляется как есть, чтобы имя переменной однозначно выводилось из
> кода модуля без таблицы соответствий. Менять регистр нельзя: ядро ищет именно такое имя.

**Проверка**

```bash
npm run modules:status
```

Ожидаемо: `Лицензия: активна (...)`, `ИТОГ: модулей 1, проблем нет`.
Если `НЕ активна` — причина написана в той же строке (см. `docs/modules-admin-guide.md` §11).

---

## 5. Пересоберите фронт

- [ ] Выполните на машине сборки

```bash
npm run build:v3
```

Нужно **всегда** (и для zip, и для npm): Vue-компоненты модуля попадают в общий бандл на сборке.

**Проверка:** в выводе сборки есть файл модуля, например `DrawioProPanel-*.js`.
Если его нет — сборка подставила заглушку: модуль не найден в `modules\<code>`/`node_modules`.

---

## 6. Перезапустите API

- [ ] Локально: `Ctrl+C`, затем

```bash
npm start
```

- [ ] Docker (демо):

```bash
docker compose -f infra/demo/docker-compose.yml up -d --build
```

**Проверка:** в логе есть строка `[modules] активно: <code>`.

---

## 7. Проверьте API двумя запросами

- [ ] Секция конфига:

```bash
curl -s <BASE_URL>/api/config | jq '.modules'
```

Ожидаемо: `"drawio-pro": { "enabled": true, "licensed": true, ... }`

- [ ] Статус модуля:

```bash
curl -s <BASE_URL>/api/drawio-pro/manifest | jq '{active, licensed, reason}'
```

Ожидаемо: `"active": true`, `"licensed": true`, `"reason": null`.

---

## 8. Зайдите на форму параметров

- [ ] Откройте **Настройки → Параметры** (`/settings/parameters`).
- [ ] Найдите группу **«Модули»** и параметр `SYS_MODULE_drawio_pro_ENABLED`
      (то же правило имени: `SYS_MODULE_<code>_ENABLED`, код строчными).
- [ ] Дальше один из двух вариантов:

| Что было в шаге 2 | Что делать здесь |
|---|---|
| задали `ENABLED_MODULES=<code>` | ничего не менять: env важнее значения в БД |
| `ENABLED_MODULES` **не** задавали | поставить значение `true` и **перезапустить API** |

> Параметры читаются в память при старте API, поэтому после правки в UI перезапуск обязателен.

**Проверка:** `npm run modules:status` → `enabled: true`.

---

## 9. Выдайте право роли

- [ ] Простой путь: **перезапустить API** — право модуля (для DrawIO Pro `drawio_pro:manage`)
      раздаётся ролям из каталога автоматически.
- [ ] Точечный путь: **Администрирование → Роли** (`/settings/administration/roles`) →
      роль «Архитектор» → отметить `drawio_pro:manage` → «Сохранить».

> Сохранение роли в UI заменяет весь набор прав роли. Если после сохранения право пропало —
> перезапустите API (права каталога вернутся) или отметьте нужное сразу.

**Проверка:** под пользователем-архитектором открыть заключение — кнопка модуля видна.

---

## 10. Проверьте в интерфейсе

- [ ] **Архитектурные заключения** → заключение → выберите решение.
- [ ] В блоке **«Схемы»** нажмите **«Заполнить из диаграммы»**.
- [ ] Откроется редактор: слева панель модуля, справа Draw.io.
- [ ] Добавьте систему/функцию/поток в панели и нажмите **«Сохранить»** в панели.
- [ ] Вернитесь на форму заключения — данные должны перечитаться.

**Проверка:** в «Системах в решении» появились добавленные записи, в «Схемах» — новая версия.
Откройте схему снова: расстановка элементов сохранилась.

---

## Если что-то не сработало

- [ ] Запустите `npm run modules:status`.
- [ ] Найдите строку с `✖` — там причина (нет пакета, несовместимость, нет лицензии, нет RBAC).
- [ ] Дальше: `docs/modules-admin-guide.md` §11 «симптом → причина → действие».

---

## Отключить модуль (без удаления)

- [ ] В env-файле уберите код из списка — `ENABLED_MODULES=` (пусто) или оставьте другие коды.
- [ ] Перезапустите API: маршруты модуля перестанут работать, кнопка исчезнет.

Альтернатива: в «Настройки → Параметры» поставить `SYS_MODULE_drawio_pro_ENABLED = false`
и перезапустить API.
