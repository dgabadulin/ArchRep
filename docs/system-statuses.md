# Справочник «Статусы систем» (issue #130)

Справочник жизненного цикла ИС: `ar_system_statuses`. Статус выбирается в карточке системы
(`ar_systems.ar_system_statuses_id`) и используется в аналитике (цвет статуса на «Карте ИТ ландшафта»).

## 1. Поля

| Поле | Тип | Назначение |
|---|---|---|
| `id` | bigserial | PK |
| `name` | varchar | наименование статуса (уникальность не требуется) |
| `description` | text | пояснение, какие системы попадают в статус |
| `extra_classification1` | varchar(255), NULL | **новое (issue #130)**: «Доп.классификация1» — текстовая метка для группировки статусов (например, «Эксплуатация», «Вывод из эксплуатации») |

Поле необязательное: существующие записи остаются с `NULL`, заполняется вручную в «Справочниках».
Имя колонки повторяет принятое в справочнике «Функциональные вертикали»
(`ar_system_owners.extra_classification1`, issue #123) — единый контракт «доп. классификации».

## 2. Миграции (dual, `.clinerules` §8)

- `DB/scripts/migrate_20261122140000_system_statuses_extra_classification1.sql` — Прод ИСАР (`psql -f`), идемпотентно;
- `DB/migrations/20261122140000_system_statuses_extra_classification1.js` — Демо ИСАР (`node-pg-migrate`), читает тот же SQL;
- в конце SQL — маркер `ar_schema_info = 20261122140000`.

Метамодель не меняется: статус — справочник, а не тип сущности/связи, версия файла «Метамодель ИСАР» не выпускается.

## 3. API

| Метод | Маршрут | Право |
|---|---|---|
| `GET` | `/api/system-statuses` (`?search`, `?excel=1`) | `references:read` или `system:read` |
| `POST` | `/api/system-statuses` | `references:write` |
| `PUT` | `/api/system-statuses/:id` | `references:write` |
| `DELETE` | `/api/system-statuses/:id` | `references:write` |

`POST`/`PUT` принимают `{ name, description, extra_classification1 }`; `name` обязателен.
Поиск (`?search`) учитывает наименование, описание и доп. классификацию.

## 4. UI

«Настройки → Справочники → Статусы систем»: в таблице колонка «Доп.классификация1»,
в модальной форме — поле для её редактирования. Экспорт в Excel включает новую колонку.

## 5. Проверки

```bash
npm test                 # schema marker: SQL ↔ JS миграции и монотонный upsert
npm run check:routes     # маршруты покрыты правами (маршруты не менялись)
npm run check:sfc        # комментирование SFC
cd frontend-v3 && npm run build
```

После применения SQL на стенде: открыть «Справочники → Статусы систем», задать доп. классификацию,
переоткрыть запись — значение сохраняется; поиск находит по значению классификации.
