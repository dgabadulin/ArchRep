# Функции систем в архитектурном заключении (Dual Listbox)

GitHub issue: https://github.com/dgabadulin/ArchRep/issues/52

**Канонический URL спеки (ветка `main`):** https://github.com/dgabadulin/ArchRep/blob/main/docs/issue-52-system-functions-dual-listbox.md

## Формулировка задачи (из issue)

На форме редактирования архитектурного заключения при добавлении системы к заключению необходимо реализовать ввод перечня функций системы следующим образом:

1. Создать таблицу привязки функций к системам **`ar_system_functions`** (`id`, `name`, `description`, `ar_system_id`).
2. Создать таблицу **`ar_adr_increment_system_functions`** (`id`, `ar_adr_increment_system_id`, `ar_system_functions_id`).
3. Открыть модальное окно **«Определение функций системы»** с **Dual Listbox** и кнопками **Сохранить** и **Отмена**. Списочные поля подписаны: **«Функции системы»** (левое) и **«Функции в решении»** (правое).

Между панелями:

- **`>>`** — перемещение из левого блока в правый;
- **`<<`** — перемещение из правого блока в левый;
- **«Создать»** — создание новой функции для левой панели: модалка с полями **Название функции** и **Примечание**; по сохранении запись сразу попадает в `ar_system_functions`. **Удаление** функций пока не предусмотрено.

После **Сохранить** на форме с Dual Listbox:

- все записи **правого** блока сохраняются в `ar_adr_increment_system_functions`;
- из **правого** списка формируется текстовая строка вида  
  `-значение 1; <перевод строки> -значение 2; <перевод строки> …`  
  и этим значением заполняется существующее поле **«Функции»** на форме (колонка комментария к строке системы в решении).

## Уточнения (согласовано)

| Тема | Решение |
|------|---------|
| **Содержимое текстового поля «Функции»** | Только **`name`** функций из правого списка, в указанном формате. |
| **Сортировка** | **Левый** список — по **алфавиту**. **Правый** — порядок задаётся **drag-and-drop**; этот порядок определяет порядок строк в тексте. |
| **Редактирование текста вручную** | **Запрещено**: поле «Функции» заполняется только из модалки (например `readonly` + вход через кнопку/действие «Определить функции»). |
| **Дубликаты** | Два раза одно и то же **`name`** у одной системы **нельзя** — проверка при сохранении новой функции (и при появлении редактирования — аналогично). |
| **Удаление системы** | Сценарий **не рассматривается**; стандартные FK/CASCADE в БД по желанию. |
| **Связь строк** | `ar_adr_increment_system_functions` ссылается на **`ar_adr_increment_systems.id`**, не на `ar_systems_id` напрямую. |
| **Доступность (a11y)** | Поддержка клавиатуры/ARIA для Dual Listbox — **не обязательна в MVP**, опционально по внутренним стандартам. |

## Технические ориентиры

- API: выдача списка `ar_system_functions` по `ar_systems_id`; создание функции; сохранение набора id для `ar_adr_increment_systems.id` с порядком для правого списка; пересборка строки в поле комментария на бэкенде или фронте (единый формат).
- Уникальность: индекс или проверка **`UNIQUE (ar_system_id, name)`** (или эквивалент), плюс понятное сообщение при дубле.

## Миграция БД

Скрипт создания таблиц — в репозитории после реализации (отдельный файл в `DB/`), выполнение на стенде до выката API/фронта.
