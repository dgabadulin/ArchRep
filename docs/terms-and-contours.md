# Термины контуров: Прод сайта, Тест сайта, Демо ИСАР, Прод ИСАР

Глоссарий для людей. Машинное правило: `.clinerules` §6 и `.cursor/rules/terms-and-contours.mdc`.

## Зачем

В проекте три публичных/локальных контура с разными жизненными циклами. Слово «прод» без уточнения
создаёт путаницу: «прод» может означать и витрину, и внутренний корпоративный контур приложения.
Поэтому в задачах, планах, отчётах и коммитах используем полные термины.

## Термины

| Термин | Что это | Адрес | Технологии |
|---|---|---|---|
| **Прод сайта** | публичная витрина (лендинг) ИСАР: «База знаний», «Видео», «Попробовать ИСАР (demo)», обратная связь (QR) | `https://archrep.ru` (`www` → 301) | статика (HTML/CSS/ассеты), отдаётся nginx; без Node |
| **Тест сайта** | локальный предпросмотр Прода сайта перед публикацией | `http://127.0.0.1:<порт>` | локальный статический сервер (`serve`, `http.server`, Live Server) |
| **Демо ИСАР** | публичный демо-стенд **приложения** ИСАР (BFF + UI + DrawIO) | `https://demo.archrep.ru` (до миграции — `archrep.ru`) | `infra/demo`: postgres + ar-api + drawio в Docker |
| **Прод ИСАР** | внутренний корпоративный контур приложения, **без доступа из интернета** | не публикуется | `infra/prod`, `deploy_local.bat` |

## Границы

- **Прод ИСАР не участвует** в задачах публикации: его env (`.env.production`), БД и миграции, деплой
  (`infra/prod`, `deploy_local.bat`, strict/ahead/dirty-гейт), Keycloak/OIDC, compose — **не трогаем**
  и в план не включаем.
- **Прод сайта** не содержит приложения: никаких `/api`, `/login`, каталогов ИСАР — только статика витрины.
  Всё «приложенческое» на `archrep.ru` уходит 301-редиректом на **Демо ИСАР**.
- **Демо ИСАР** переезжает с корня на поддомен без пересоздания стека: меняется только домен в nginx
  и `CORS_ORIGIN` / `DRAWIO_EMBED_BASE` (и OIDC-настройки, если SSO включён).
- **Тест сайта** — это проверка `Прода сайта`, а не Демо ИСАР; выполняется до публикации и только по
  `http://127.0.0.1:<порт>` (не по `file://`).

## Соответствие имён и файлов

| Имя / путь | Контур |
|---|---|
| `archrep.ru`, `www.archrep.ru` | **Прод сайта** (статика) |
| `demo.archrep.ru` | **Демо ИСАР** |
| `demo.archrep.ru/drawio/` (или `drawio.archrep.ru`) | DrawIO для **Демо ИСАР** |
| `127.0.0.1:<порт>` | **Тест сайта** |
| `infra/demo/**`, `deploy_demo.bat` | **Демо ИСАР** |
| `infra/prod/**`, `deploy_local.bat` | **Прод ИСАР** (не трогаем) |
| `site/**` (появится), `infra/site/**` | **Прод сайта** и его деплой |
| `docs/deploy-prod-vs-demo.md` | историческое описание `prod` = **Прод ИСАР** |

## Как писать

- «Открыть **Прод сайта**», «опубликовать **Прод сайта**», «проверить в **Тесте сайта**»,
  «перенести **Демо ИСАР** на `demo.archrep.ru`».
- Не писать: «прод», «прод-стенд», «продакшн», «выкатить на прод» без уточнения контура.
- В коммитах и release notes: если изменение касается витрины — `feat(site): …`; если стенда —
  `chore(demo): …`; **Прод ИСАР** в сообщениях не упоминается.

## Доменная схема (целевая)

```
archrep.ru        → Прод сайта  (nginx root /var/www/archrep.ru)
www.archrep.ru    → 301 → archrep.ru
demo.archrep.ru   → Демо ИСАР   (nginx proxy → 127.0.0.1:3000)
demo.archrep.ru/drawio/ → DrawIO Демо ИСАР (nginx proxy → 127.0.0.1:8080)
127.0.0.1:8080    → Тест сайта  (локально, не публикуется)
```

Переходный режим: до публикации Прода сайта корень `archrep.ru` продолжает обслуживать Демо ИСАР;
после — все «приложенческие» пути на корне отдают 301 на `demo.archrep.ru`.
