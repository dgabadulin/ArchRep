## Папка с промптами для ИИ

Здесь храним текстовые промпты и сценарии работы с ИИ, которые помогают развивать и сопровождать архитектурный репозиторий.

### Задачи из GitHub Issues

Чтобы ассистент брал формулировку задачи из GitHub Issue:

1. **Установи и войди в GitHub CLI** (один раз):
   - Установка: [cli.github.com](https://cli.github.com/) или `winget install GitHub.cli`.
   - В терминале: `gh auth login` и выбери репозиторий/аккаунт.
2. **В чате с ассистентом напиши**, например:
   - «Задача из #12»
   - «Сделай issue 5»
   - «Возьми промпт из issue #7»
3. Ассистент выполнит `gh issue view <номер>`, получит заголовок и тело issue и будет выполнять задачу по этому описанию.

Если `gh` не установлен, можно скопировать текст issue в чат или вставить ссылку — ассистент сможет работать по вставленному тексту.

---

### Как сохранить промпт

1. **Вручную:** скопируй текст запроса в новый файл по образцу `_template.md`.
2. **Через ассистента:** в конце обсуждения попроси: «сохрани этот промпт в docs/prompts как …» — будет создан файл с заполненным шаблоном.
3. В проекте включено правило для Cursor (`.cursor/rules/prompts.mdc`): ассистент в конце решения задачи предлагает сохранить промпт; запись в файл только по твоей явной просьбе.

### Шаблон

Используй **`_template.md`** как основу: контекст, цель, текст промпта, формат ответа, критерии готовности.

### Рекомендуемые имена файлов

- `backend_refactor.md` — промпты для рефакторинга/расширения backend‑API.
- `db_cleanup.md` — промпты для миграций и очистки БД.
- `ui_design.md` — промпты для проектирования экранов фронтенда.
- `togaf_metamodel.md` — промпты для проектирования метамодели под TOGAF.

Общие правила:

- Один файл — один чётко сформулированный сценарий.
- В начале файла описывать:
  - **Контекст**: какие схемы/файлы/среды используются.
  - **Цель**: что должен получить архитектор/разработчик в итоге.
  - **Формат ответа**: код, список шагов, архитектурная схема и т.п.
- При изменении практики обновлять соответствующий промпт и коммитить изменения.
