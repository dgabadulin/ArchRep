# Промпт: draw.io в архитектурное решение через БД

## Контекст

- **Проект/репозиторий:** ArchRep (frontend-v3 + backend Node.js + PostgreSQL).
- **Файлы/схемы:** модуль архитектурных решений, редактор диаграмм, справочники систем и интеграций.
- **Ограничения:** нужно сохранять и исходную диаграмму, и структурированные данные; обеспечить валидацию на backend; не ломать существующие архитектурные решения.

## Цель

Спроектировать и реализовать MVP интеграции draw.io (diagrams.net), в котором пользователь выбирает системы и типы интеграций из панели инструментов, связывает их на диаграмме, а при сохранении данные попадают в БД и автоматически включаются в архитектурное решение (схема + структурированное описание связей).

## Промпт для ИИ (скопировать в чат)

```
Нужно спроектировать MVP для интеграции draw.io (diagrams.net) в наш ArchRep.

Требование:
1) В редакторе должна быть панель (палитра) с нашими системами и типами интеграций.
2) Пользователь должен уметь:
   - выбрать систему,
   - указать функцию системы,
   - провести стрелку интеграции и выбрать ее тип.
3) При сохранении должны сохраняться:
   - исходная диаграмма (mxfile/xml),
   - превью (svg или png),
   - структурированные данные (узлы/функции/связи/типы интеграций) в БД.
4) После сохранения содержимое диаграммы должно попадать в архитектурное решение:
   - отображение схемы,
   - таблица интеграций, сгенерированная из структурированных данных.

Сделай предложение по реализации:
- архитектура решения (frontend/backend/БД),
- структура таблиц БД,
- API-контракты,
- правила валидации,
- стратегия версионирования диаграмм,
- план внедрения на 2-3 итерации,
- основные риски и способы их снизить.

Если есть альтернативы (embed diagrams.net vs импорт файлов), кратко сравни и дай рекомендацию.
```

## Формат ответа

- Краткий план реализации по слоям: frontend, backend, БД.
- SQL-скелет таблиц/полей для MVP.
- API-контракты (request/response) для сохранения и чтения диаграммы.
- Чек-лист валидации перед сохранением.
- Пошаговый roadmap (2-3 итерации) с ожидаемым результатом каждой итерации.
- Блок рисков и mitigation.

## Критерии готовности

- Описан рабочий MVP-подход с palette систем и интеграций в редакторе.
- Есть модель хранения диаграммы и структурированных данных в БД.
- Определены API для save/load и включения диаграммы в архитектурное решение.
- Зафиксированы обязательные проверки данных (валидаторы).
- Подготовлен реалистичный план внедрения по итерациям.
- Указана рекомендуемая стратегия (предпочтительно embed diagrams.net) и обоснование.
