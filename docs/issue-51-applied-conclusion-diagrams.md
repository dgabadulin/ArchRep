# Диаграммы решений в архитектурном заключении (Draw.io)

GitHub: https://github.com/dgabadulin/ArchRep/issues/51

## Формулировка задачи (из issue)

Необходимо на экранной форме архитектурного заключения сделать блок **«Схемы»** (дочерний от блока «решения»).

В блоке должна быть кнопка **«Создать схему решения»**. При нажатии формируется файл диаграммы и отображается в таблице под кнопкой.

Под кнопкой — таблица версий диаграммы с атрибутами:

- имя файла: **имя решения в блоке** + номер очередной версии (`v1`, `v2`, `v3`);
- дата и время создания: **DD.MM.YYYY HH:MM:SS**;
- дата и время последнего редактирования: **DD.MM.YYYY HH:MM:SS**;
- имя пользователя, последним внёсшего изменения (**пока не заполняется** — после внедрения авторизации).

Действия по строке:

| Действие | Поведение |
|----------|-----------|
| **Обновить** | Пересобрать диаграмму по актуальным данным решения с учётом ранее сохранённой раскладки вершин в Draw.io, затем **открыть** диаграмму в новой вкладке для просмотра/правки. |
| **Открыть** | Открыть диаграмму в соседней вкладке с возможностью правок и **сохранения в БД**. |
| **Скачать** | Выгрузить `.drawio` в папку «Загрузки» браузера. |
| **Удалить** | Жёсткое удаление записи; перед удалением — модальное подтверждение. |

## Договорённости (продукт и техника)

1. **«Создать схему решения»** — каждое нажатие создаёт **новую версию** (следующий `vN`), без проверки «изменились ли данные».
2. **«Обновить»** доступно **для каждой строки**; обновляется **именно эта версия** (запись `id`), остальные версии не трогаются.
3. **Merge данных и раскладки:** при пересборке для вершин с id `sys-{ar_systems_id}` сохраняются координаты из предыдущего mxfile; подписи и рёбра пересобираются по текущим системам и интеграциям инкремента. Связи: id `rel-{id_связи_инкремента}`.
4. **Конкурентное редактирование:** действует правило **«последнее сохранение победило»**; в интерфейсе редактора кратко предупреждение, если открыто несколько вкладок.
5. **Удаление** — **жёсткое** (запись удаляется из БД).
6. Поле **пользователь** — остаётся пустым до реализации авторизации в API сохранения.

## Реализация в репозитории

- Таблица: `archrep.ar_adr_increment_diagrams` — скрипт `DB/ar_adr_increment_diagrams.sql`.
- API: префикс `/api/increments/:incrementId/diagrams` (список, создание, получение, merge, PUT mxfile, DELETE).
- Генерация/merge: `backend/incrementDiagram.js`.
- Фронт: блок «Схемы» в `DecisionAppliedForm.vue`, редактор — `DiagramEditorView.vue` (embed Draw.io).
- Публичный параметр **`DRAWIO_EMBED_BASE`** в `/api/config` — базовый URL инстанса Draw.io (например `https://host/drawio`).

## Миграция БД

Выполнить на сервере скрипт `DB/ar_adr_increment_diagrams.sql` (один раз).
