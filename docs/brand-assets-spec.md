# ТЗ: логотип и иконки ИСАР / archrep.ru — расчёт от слотов вставки

**Статус:** поставка дизайнера получена и встроена (см. §11)
**Принцип:** размеры считаются **не от существующих файлов**, а от места вставки: размер слота в CSS → ×DPR (1×/2×/3×) → требуемый пиксельный размер и формат.

---

## 0. Короткое ТЗ (можно отправлять как есть)

- **п. 1 — логотип в шапке левого меню:** высота **32 px** (ширина до 224 px, ориентир 110–130 px), фон **белый #FFFFFF**, файлы **SVG + PNG 368×96 px** (3×) с прозрачным фоном, **цветная** версия; контраст к белому ≥ 3 : 1.
- **п. 4 — favicon:** **знак без надписи**, упрощённая прорисовка под малый размер, файлы **SVG + PNG 16 / 32 / 48 px**, **ICO** (16/24/32/48/64/128/256), **PNG 180×180 без прозрачности** (iOS), **PNG 192 и 512 px** (PWA) с maskable-версиями; контраст ≥ 3 : 1 на белом **и** на тёмном фоне.

## 2. ИСАР — приложение

### 2.1 Левое меню — главный слот (приоритет №1)

Фактические параметры вёрстки: сайдбар **260 px**, отступы шапки сайдбара — **17,6 px** по горизонтали и **8 px** по вертикали (высота шапки 48 px, как у шапки контента).

- Полезная ширина слота: 260 − 2 × 17,6 = **224,8 px** → логотип не должен быть шире **224 px**.
- Полезная высота слота = **32 px** (допустимо 28–32): шапка сайдбара должна совпадать по высоте с тёмной шапкой контента (48 px), иначе линия под шапками не сходится.
- Рекомендуемая ширина при такой высоте: **110–130 px** (≈ 55 % слота) — остаётся воздух справа.
- Обязательные файлы: `logo.svg` (эталон), `logo.png` (≥ 368 × 96 px при 3× DPR), `logo-white.svg/.png` (для тёмного фона), `logo-mono.svg` (печать).

**Фон слота (важно для п.1):**

- Сайдбар залит чистым белым — `--ar-surface: #ffffff`; разделители — `#e4e6ea` (1 px). Тёмной темы в приложении нет (`prefers-color-scheme` / `data-theme` не реализованы).
- Для п.1 нужна **цветная версия под белый фон**; белая и инверсная здесь не применяются.
- Hover: логотип показывается с непрозрачностью **75 %** — проверить читаемость и в этом состоянии.
- Контраст `#00ABA7` на белом — **2,7 : 1** (ниже 3 : 1). Для 32 px лучше тёмный teal `#00807C` (≈ 4,8 : 1) либо утолщённые штрихи.
- Прозрачность PNG обязательна: «запечённый» фон даст видимую плашку, а на hover она станет темнее логотипа.

### 2.2 Экран входа

- Карточка `min(420px, 100%)` с отступом 24 px → полезная ширина **372 px**.
- Логотип: высота **56 px**, ширина ≤ 372 px; ориентир 200–230 px.
- Файлы: SVG + PNG **642 × 168 px** (3×).

### 2.3 Шапка контента (необязательный слот)

- Высота шапки `min-height: 3rem` = **48 px**, боковые отступы 20 px.
- Высота логотипа в этом слоте — **24–28 px** (ширина 92–107 px при пропорции ≈ 3,8 : 1).
- Фон тёмный (`#1a1d2e` → `#252842`) → нужна **белая** версия.

### 2.4 Favicon и системные иконки

| Слот | Физический размер | Файл | Обязательные условия |
|---|---|---|---|
| Вкладка браузера | 16 × 16 | `favicon.svg` (приоритет), `favicon-16.png` | отдельная **упрощённая** версия знака (см. §5.3) |
| Вкладка Retina | 32 × 32 | `favicon-32.png` | тот же знак, без надписи |
| Закладки, история | 48 × 48 | `favicon-48.png` | |
| Windows, старые браузеры | 16–256 | `favicon.ico` — **7 кадров**: 16, 24, 32, 48, 64, 128, 256 | каждый кадр — отдельный экспорт, не апскейл |
| iOS, домашний экран | 180 × 180 | `apple-touch-icon.png` | **без прозрачности**, скругления не рисовать (iOS скругляет сам) |
| App Store / витрина | 1024 × 1024 | `apple-touch-icon-1024.png` | без alpha |

Иконочный минимум для заказа: **знак 512×512 (цветной, белый, моно) + `favicon.svg` + PNG 16/32/48/180/192/512 + ICO**.

## 3. archrep.ru — сайт-витрина

Стартовая страница — витрина 2×2: «База знаний», «Видео», «Попробовать ИСАР (demo)», «Обратная связь (QR)».

### 3.1 Шапка сайта

- Контейнер 1200 px, боковые отступы 24 px → полезная ширина **1152 px**; высота шапки **64 px**.
- Логотип: высота **40 px** (диапазон 32–40), ширина ≈ 150 px при пропорции 3,8 : 1.
- Файлы: SVG + PNG **306 × 80** (2×) и **459 × 120** (3×). Нужны версии для светлой и тёмной шапки.

### 3.2 Плитки витрины (4 иконки)

- Слот иконки: контейнер **64 × 64 px**, сама иконка **32 × 32 px**.
- Файлы: SVG с сеткой 24 × 24, толщина штриха 2 px, скругления 2 px (стиль Lucide — приложение уже использует Lucide).
- Состав: база знаний, видео, demo/запуск, обратная связь/QR. Цвет: 1 (`#00ABA7`) или 2 (teal + тёмный), без градиентов и теней.

### 3.3 QR-блок обратной связи

- QR 160 × 160 px генерируется технически; от дизайнера нужна **рамка/подложка 200 × 200** (SVG).
- Тихая зона ≥ 4 модулей QR не перекрывается графикой, фон под QR — белый, контраст ≥ 4,5 : 1.

### 3.4 OG-превью (мессенджеры, соцсети)

- Холст **1200 × 630**, sRGB, PNG/JPG ≤ 300 КБ.
- Логотип в слоте **320 × 84** в левом верхнем углу, отступ 60 px; безопасное поле 60 px со всех сторон.
- Текст не мельче 40 px; проверить в Telegram и VK при уменьшении до 25 %.

### 3.5 Аватар канала (Telegram / VK)

- **512 × 512**, знак в центральном круге, safe zone **20 %** (маска круглая).
- Фон контрастный, знак не должен «тонуть» при 40 px.

### 3.6 Решение по бренду (принять до заказа)

- **Вариант «А» (по умолчанию):** archrep.ru — витрина бренда ИСАР. Отдельный логотип не нужен: тот же знак + надпись, в шапке допускается подпись «archrep.ru» текстом сайта.
- **Вариант «Б»:** archrep.ru — самостоятельный бренд портала. Тогда дополнительно заказывается отдельный знак и связка «archrep.ru ↔ ИСАР».

## 5. Требования к файлам

### 5.1 SVG (главный формат)

- Текст — **в кривые** (outline), шрифтов в файле быть не должно.
- Прозрачный фон; никаких внешних стилей — только inline `fill`/`stroke`, чтобы файл одинаково работал как favicon и как `<img>`.
- Без фильтров, масок, градиентов, blur, `clip-path` (если нужны — согласуются отдельно).
- `viewBox` по контуру, без «пустых» полей; `width`/`height` не фиксировать жёстко.
- ≤ 15 КБ на файл; без внешних ссылок и встроенных растров.
- Проверка: одинаковый рендер в Chrome, Figma, Illustrator.

### 5.2 PNG

- 32-bit RGBA (alpha), профиль **sRGB**.
- Без белой подложки, тени, свечения, «резкости» по краям.
- Не апскейлить: каждый размер экспортируется из вектора.
- Проверить на белом и на тёмном (`#1a1d2e`) фоне — не должно быть ореола.
- Фон «запекать» только там, где это требуется (apple-touch-icon).

### 5.3 Малые размеры и favicon — отдельная прорисовка

- толщина штриха ≥ 10–12 % ширины иконки (при 16 px это 1,6–2 px);
- минимальный диаметр окружности ≥ 3 px при 16 px;
- для 16 px допускается **упрощённый вариант** знака — отдельный файл, а не масштаб большого;
- надпись в favicon не используется вообще.

### 5.4 ICO

- 7 кадров: 16, 24, 32, 48, 64, 128, 256 px.
- Каждый кадр — собственный PNG-экспорт (32-bit), не апскейл; 256-й кадр — PNG внутри ICO.

### 5.5 OG / social preview

- 1200 × 630 (GitHub — 1280 × 640), sRGB, ≤ 300 КБ.
- Значимый контент — в центральных 90 %, отступы 60 px.
- Крупный логотип + одна короткая строка; превью сжимается до ~300 × 157 px.

### 5.6 Печать

- CMYK (FOGRA39 / Coated), вылеты 3 мм, шрифты в кривых.
- Форматы: AI + PDF + EPS; отдельно монохромная версия (1 краска).

## 6. Правила построения знака

- **Охранное поле:** 0,5 × высоты знака (минимум 8 % ширины) со всех сторон; в файлах — реальный прозрачный отступ.
- **Минимальные размеры:** горизонтальный логотип — 60 px / 20 мм по ширине; знак — 16 px / 6 мм.
- Пропорции не менять, текст не наклонять и не «поджимать» вручную.
- Версии: цветная, белая, моно-чёрная, инверсная (для фото и сложных фонов — на плашке).
- Логотип не перекрашивать в акцентный цвет интерфейса `#00e5cc` — он светлее знака и «слепнет» на белом.
- Латиница: нужна версия **ISAR** (GitHub, англоязычные документы) в той же графике; **ArchRep** — только если решите его использовать.

## 7. Цвет и контраст (критично для мелких иконок)

| Пара | Контраст | Вывод |
|---|---|---|
| `#00ABA7` на белом | ≈ 2,7 : 1 | ниже 3 : 1 — для 16 px и мелкой графики **недостаточно** |
| `#00807C` (тёмный teal) на белом | ≈ 4,8 : 1 | годится для 16 px, одноцветных иконок и мелкого текста |
| `#00ABA7` на `#1a1d2e` (тёмная шапка) | ≈ 6,0 : 1 | на тёмном фоне читается хорошо |

Что нужно от дизайнера: палитра с HEX / RGB / CMYK + **отдельный тёмный вариант** для мелких размеров. Проверка — по WCAG: ≥ 3 : 1 для графики, ≥ 4,5 : 1 для текста.

## 9. Чек-лист приёмки

- [ ] логотип читается в слоте **224 × 32** (меню) и **372 × 56** (вход);
- [ ] знак различим в **16 × 16** и **32 × 32** — проверять в реальной вкладке браузера при 100 % масштабе;
- [ ] на тёмном фоне `#1a1d2e` нет ореола, белая версия читается;
- [ ] iOS 180 × 180: без прозрачности, знак не обрезан круглой маской;
- [ ] maskable: знак внутри центральных 80 %;
- [ ] ICO: 7 кадров, каждый резкий (16-й — не «каша»);
- [ ] OG: текст читается при ширине 300 px;
- [ ] SVG: нет шрифтов, фильтров, растров; вес ≤ 15 КБ;
- [ ] PNG: alpha там, где нужна, и отсутствует у `apple-touch-icon`; sRGB;
- [ ] имена файлов совпадают со списком из §8;
- [ ] переданы исходники (`.ai`/`.fig`) и бренд-гайд;
- [ ] переданы права на использование (репозиторий — Apache 2.0, ассеты лицензируются отдельно).

## 10. Как это ложится в репозиторий

1. Файлы копируются в `frontend-v3/public/` под служебными именами из §8.
2. Статика отдаётся через `express.static(frontend-v3-dist)`, поэтому после замены: `cd frontend-v3 && npm run build`.
3. `frontend-v3/index.html` подключает `favicon.svg` → `favicon.png` → `favicon.ico` → `apple-touch-icon`.
4. Сайдбар: `.logo-img { height: 32px; width: auto }`, шапка — `padding: 0.5rem 1.1rem` (48 px). Экран входа: `.logo { height: 56px }`.
5. Иконки генерирует `scripts/make-brand-assets.ps1`: нормализует SVG дизайнера, читает геометрию знака из `favicon.svg` (`<line>`/`<circle>`) и рендерит ICO/PNG/apple/OG.
6. Письма: `logo-email.png` лежит в `public/` и подключается абсолютным URL (сейчас HTML-письма идут без логотипа).
