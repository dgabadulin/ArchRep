# ADR. Единое ядро ИСАР: отказ от подключаемых модулей (v4.0.0)

**Статус:** принято (2026-11-05) · **Заменяет:** `docs/modules-contract.md`, `docs/module-license-key.md`,
`docs/modules-admin-guide.md`, `docs/modules-connect-checklist.md` (удалены)

## 1. Контекст

В 3.x в ядре была инфраструктура подключаемых модулей (`backend/modules/*`, фронтовый реестр
поверхностей, реестр `archrep.isar_modules`, лицензионный гейт Ed25519), и модуль
`@isar/drawio-pro` поставлялся способом **build-time**: клиент получал исходники модуля и собирал
образ ядра у себя.

Проблема: **передача JS/`.vue`-кода модуля клиенту ломает коммерческую модель**:
- код читаем и копируем, лицензионный гейт в этом же коде снимается правкой нескольких строк;
- «механизм расширения» как продукт не работает: расширение = отданный исходник;
- обновление модуля означает пересборку ядра у клиента → расползание поддержки.

Офлайн-лицензия (Ed25519-ключ) защищает от подделки ключа, но не от копирования кода — значит
для платной функциональности нужна поставка, при которой код не попадает к клиенту, либо
функциональность должна быть частью ядра.

## 2. Решение

**Перейти к единому ядру.** Подключаемые модули (и их инфраструктура) удаляются; функциональность
развивается в ядре, поставка — готовым образом (`vendor-build`). Расширяемость для сторонних
систем — через публичный REST API и вебхуки, без исполнения чужого кода внутри ядра.

Причины выбора:
- единая кодовая база и один процесс обновления;
- код всегда остаётся у правообладателя (клиент получает контейнер, а не исходники);
- нет двойных контрактов (ядро/модуль) и адаптеров под чужие форматы;
- меньше поверхность поддержки: −13 файлов загрузчика, −7 тестов, −4 документа.

Альтернативы отклонены: `external`-модули (код у вендора, iframe/HTTP) — сложность SSO и UI,
отложено; `vendor-build` с сохранением модулей — сохраняет двойной контракт и адаптеры.

## 4. Что осталось (ядро)

- **Редактор схем** (`DiagramEditorView.vue`): DrawIO-embed через `DRAWIO_EMBED_BASE`, загрузка
  `.drawio` из решения, автосохранение в БД (`PUT /api/increments/:id/diagrams/:diagramId`).
- **Валидация и нормализация mxfile** (`backend/adrIncrements.js`): лимит `DRAWIO_MXFILE_MAX_MB`,
  нормализация ссылок payload, `increment_id` в ответе `POST/PUT /full`.
- Параметр `DRAWIO_MXFILE_MAX_MB` (группа «Модули» переименована в «Схемы»? — нет: остаётся как есть).

## 5. Последствия

**Для администратора (миграция при обновлении):**
1. Применить `DB/scripts/migrate_20261106120000_drop_isar_modules.sql` (prod — вручную):
   удаляет `archrep.isar_modules`, параметр `SYS_MODULE_drawio_pro_ENABLED`, право `drawio_pro:manage`.
2. Удалить из env: `ENABLED_MODULES`, `SYS_MODULE_<code>_*`, `SYS_MODULE_LICENSE_*`,
   `SYS_INSTANCE_ID`, `SYS_INSTALL_REF`, `MODULES_DIR` (больше не читаются).
3. Удалить каталог `modules/` и пакет `@isar/drawio-pro` (если ставился).
4. Кнопка «Заполнить из диаграммы» и API `/api/drawio-pro/*` больше не существуют — при внешних
   интеграциях, завязанных на них, требуется доработка.

**Для разработки:** новая функциональность = код ядра (без плагинов); сторонние интеграции — через
`/api/*` и вебхуки; схемы — через ядровой редактор.

**Обратная совместимость:** нет. Релиз **MAJOR 4.0.0**.
