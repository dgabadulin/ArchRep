# Тип интерфейса ИС (issue #129)

Классификационный атрибут информационной системы: какие пользовательские интерфейсы у неё есть.
Одна ИС может иметь **несколько** типов (например, Web + Mobile), поэтому модель — справочник
и связь «многие-ко-многим», а не одно поле-FK.

## 1. Модель данных

| Объект | Назначение |
|---|---|
| `archrep.ar_system_interface_types` | справочник: `id`, `code` (уникальный, устойчив к переименованию), `name` (уникальное), `description` |
| `archrep.ar_system_interface_type_links` | связь ИС ↔ тип: `ar_systems_id`, `ar_system_interface_types_id`, `UNIQUE (ar_systems_id, ar_system_interface_types_id)` |

Ограничения:

- `ar_systems_id` → `ar_systems(id) ON DELETE CASCADE` — при удалении ИС связи уходят;
- `ar_system_interface_types_id` → `ar_system_interface_types(id) ON DELETE RESTRICT` — удалить
  используемый тип нельзя (API отвечает `409`);
- типы задаются и корневым ИС, и модулям (`ar_systems.parent_ar_systems_id <> NULL`) — ограничений нет.

Предзаполнение: `web/Web`, `desktop/Desktop`, `mobile/Mobile`, `terminal/Терминал`
(«Консольный интерфейс (TUI)»).

Миграции — dual (`.clinerules` §8):

- `DB/scripts/migrate_20261122130000_system_interface_types.sql` (Прод ИСАР, `psql -f`);
- `DB/migrations/20261122130000_system_interface_types.js` (Демо ИСАР, `node-pg-migrate`).

**Схема метамодели не меняется**: тип интерфейса — атрибут/классификатор, а не тип сущности
и не тип связи. Версия файла «Метамодель ИСАР» не выпускается.

## 2. API

| Метод | Маршрут | Право |
|---|---|---|
| `GET` | `/api/system-interface-types` (`?search`, `?excel=1`) | `references:read` или `system:read` |
| `POST` | `/api/system-interface-types` | `references:write` |
| `PUT` | `/api/system-interface-types/:id` | `references:write` |
| `DELETE` | `/api/system-interface-types/:id` | `references:write` |

`POST`/`PUT` принимают `{ code, name, description }`; конфликт уникальности → `409`.

Карточка ИС:

- `GET /api/ar-systems`, `GET /api/ar-systems/:id` возвращают `interface_types` (имена через запятую)
  и `interface_type_ids` (массив id, отсортирован);
- `POST /api/add-ar-systems`, `PUT /api/update-ar-systems/:id` принимают `interface_type_ids: number[]`;
  шапка и связи сохраняются **одной транзакцией** (`withTransaction`), при ошибке — откат.
  Если ключа `interface_type_ids` в теле нет, связи не изменяются (совместимость клиентов).

## 3. UI

- Карточка ИС, вкладка «Данные системы»: группы «Организации» и «Ответственность» (рамки),
  «Тип интерфейса» — вложенная рамка в строке с «Тип хостинга»; значения выбираются чекбоксами
  («чипсами»), можно несколько. «Примечание» с формы скрыто, поле `comment` остаётся в API и Excel.
- Реестр ИС: колонка «Тип интерфейса» (по умолчанию видима), значения через запятую;
  поиск учитывает типы (`EXISTS` по связи), фильтр — стандартный, по склеенной строке
  («Web, Mobile» как одно значение). Отдельного фильтра «только Mobile» нет — осознанное ограничение.
- «Справочники» → вкладка «Типы интерфейса ИС»: CRUD, поиск, экспорт в Excel.

## 4. Excel

- Экспорт реестра ИС: колонка «Типы интерфейса (interface_types)» — имена через `; `
  (в шаблоне импорта — через `;` или `,`); служебная колонка «ID типов интерфейса (interface_type_ids)».
- Импорт (`template_version = 3`): поле «Типы интерфейса», несколько значений через `;` или `,`;
  неизвестное название → ошибка строки; пустая ячейка при обновлении — связи не меняются
  (как у остальных справочников).
- Проверка списка в шаблоне для этого поля — в режиме **warning**: Excel не блокирует составное
  значение, но подсказывает значения справочного листа «Справочник_типы_интерфейса».

## 5. Права

Отдельных прав не вводится: чтение справочника доступно по `system:read` (форма) и `references:read`,
изменение — `references:write`. Форма сохраняет связи по `system:write`.
