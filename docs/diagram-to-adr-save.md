# «Заполнить из диаграммы»: состав решения из схемы draw.io

> Перенос функциональности модуля **DrawIO Pro** в ядро (v4.x). Модульный слой удалён в v4.0.0
> (`docs/adr-single-core.md`), поэтому палитра — часть ядра, а не подключаемый модуль.

## 1. Сценарий

1. На форме архитектурного заключения (`/decisions/applied/:id/edit`) в блоке **«Схемы»** для
   выбранного решения — кнопка **«Заполнить из диаграммы»**.
2. Открывается новая вкладка: слева **палитра состава решения**, справа — редактор draw.io
   (`DiagramEditorView` с `?palette=1`).
3. В палитре добавляются **системы** (из реестра или новые), их **функции**, **потоки** (связи);
   у каждой строки — статус «в заключении» из справочника.
4. Любое изменение сразу перерисовывает схему. До нажатия **«Сохранить»** в реестры ничего не пишется.
5. «Сохранить» = одна транзакция ядра (`PUT /full`, режим `merge` по своему решению), затем
   перекодирование черновых id и запись `.drawio` в схему решения.

## 3. Идентификаторы ячеек

Схема повторяет серверный генератор (`backend/incrementDiagram.js`), иначе merge раскладки
(`mergeMxfileWithData`) не находит ячейку:

| Объект | Ячейка |
|---|---|
| система из реестра | `sys-{ar_systems_id}` |
| новая система (до сохранения) | `draft-sys-{key}` |
| связь решения | `rel-{ar_adr_increment_relations.id}` |
| новая связь (до сохранения) | `draft-rel-{key}` |

После сохранения черновые id перекодируются в реальные (`remapCellIds`), поэтому повторное
«Обновить» из формы сохраняет раскладку.

## 4. Статусы и функции на схеме

- Статус объекта в заключении хранится в стиле ячейки: `isarStatus=ADR_INCR_*`. Стиль переживает
  перетаскивание и читается при разборе; сервер при «Обновить» перерисовывает заливку по
  `DRAWIO_NODE_STYLE`.
- Функции системы отображаются **строками в теле узла** с маркерами статуса
  (`+ • ✓ - ?`, параметр `DRAWIO_SYSFUNC_MARKERS`) — как в существующем генераторе (issue #93).
  Вложенных ячеек `fn-*` палитра не создаёт: серверный формат остаётся единственным.
- HTML значения узла формируется побайтово совместимо с серверным `buildNodeHtmlValue`.

## 5. Изолированность

До «Сохранить» выполняются только `GET`-запросы справочников (`/api/ar-systems`,
`/api/ar-systems/:id/system-functions`, `/api/integration-flows`, `adr-*-statuses`).
Весь состав живёт в памяти вкладки; закрытие вкладки без сохранения ничего не меняет в БД.

## 6. Контракт сохранения

```
DiagramPalette → useDiagramDraft.save({ xml })
  1) reconcile(xml)                  нарисованное (parseMxfile) → модель: удалённые ячейки убираются
  2) validate()                      правила статусов
  3) PUT /api/decisions/applied/:id/full  { increments:[…], increments_mode:'merge', increment_id }
  4) remapCellIds(xml, ответ.systems/relations)   draft-* → sys-{id} / rel-{id}
  5) GET  /api/increments/:incId/diagrams         актуальная версия после пересоздания решения
  6) PUT  /api/increments/:incId/diagrams/:id     { mxfile }
```

`increments_mode: 'merge'` (адаптер `PUT /full`) пересоздаёт только своё решение — остальные
решения заключения не затрагиваются.

## 7. Ограничения

- Состав вводится палитрой; правка текста в узлах draw.io не является источником истины —
  при «Сохранить» подписи берутся из черновика (из холста читаются наличие ячеек, статусы и раскладка).
- Вкладка формы заключения не узнаёт о сохранении из соседней вкладки автоматически:
  данные перечитываются при следующем открытии/обновлении формы.
- Тип `DRAWIO_NODE_STYLE` не публикуется в `/api/config`, поэтому предпросмотр в палитре
  использует собственные цвета; после сохранения стиль задаёт сервер.

## 8. Предусловие и диагностика

Палитра и редактор схем требуют заданного адреса draw.io — параметр `DRAWIO_EMBED_BASE`
(env API или «Настройки → Параметры», группа «Draw.io»). Без него форма заключения
показывает предупреждение и **не открывает** вкладку.

Проверка фактического состояния backend:

| Что | Ожидаемо |
|---|---|
| `GET /api/version` → `config.drawio_configured` / `config.drawio_embed_base` | `true` и ваш URL |
| Лог API при старте: `[config] DRAWIO_EMBED_BASE: …` | ваш URL (или `(не задан — схемы не откроются)`) |
| `GET /api/config` → `DRAWIO_EMBED_BASE` | тот же URL; ответ с `Cache-Control: no-store` |

Изменение параметра в UI применяется сразу (CRUD параметров перечитывает кэш `loadParams`),
но SPA держит `/api/config` с момента загрузки — нужна перезагрузка страницы. Если параметр
в UI есть, а `drawio_configured = false` — API смотрит в другую БД (сравните `DB_HOST/DB_NAME`
из лога старта). Подробнее: `docs/deploy-drawio-docker.md`.
