# Фильтрация по колонкам в табличных формах (Excel-подобная)

GitHub: https://github.com/dgabadulin/ArchRep/issues/72

**Статус:** rollout групп A + B + C реализован (15 экранов); проверка на стенде — вручную.

---

## Контекст

В `frontend-v3` табличные списки (реестры, справочники, админка) используют общий паттерн:

- глобальный поиск — `TableToolbar` + `useListSearch` (`?search=` в URL), запрос на backend;
- сортировка по клику на заголовок — на клиенте (`sortedList` / `sortedSystems`);
- выбор видимых колонок — «Вид», cookie `ar_cols_<tableId>` (`tableColumns.js`);
- предпочтения сортировки — cookie `ar_sort_<tableId>`.

**Нет** фильтрации по отдельным колонкам (автофильтр Excel: выпадающее меню на заголовке, несколько условий одновременно).

Пилотный экран: **Каталог ИС** (`SystemsList.vue`, `tableId = systems`).

---

## Цель

Добавить **дополнительный** механизм фильтрации по колонкам по аналогии с автофильтром Excel (упрощённый MVP), не заменяя глобальный поиск.

После пилота — тот же механизм на экранах **групп A, B, C** (см. ниже). Справочники `ReferencesV2` и админка — **вне scope #72**.

---

## Принятые решения (ответы заказчика)

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Область данных фильтра | **Клиентская** фильтрация по уже загруженным строкам (после глобального `search` и ответа API). Серверные column-filters — вне scope пилота. |
| 2 | Текстовые колонки | Условие **«содержит»** (подстрока, без учёта регистра). Список уникальных значений с чекбоксами для текстовых колонок **не** требуется. |
| 3 | Сохранение состояния | **Да**, в cookie (как «Вид» и сортировка), по `tableId`. |
| 4 | Экспорт в Excel | Выгружать **только отфильтрованные** строки (с учётом глобального поиска и column-filters). |
| 5 | Пилот | **Каталог ИС** (`/systems`, `SystemsList.vue`). |

### UX v2 (2026-09-02)

| Тема | Решение |
|------|---------|
| Enum «Снять все» | Как в Excel: после **ОК** с нулём галочек — **0 строк** (`mode: none`). Сценарий: снять все → отметить нужное → ОК. |
| Применение фильтра | Только по **ОК** (text и enum/bool); **Отмена** / Esc / клик вне — без изменений. |
| «Сбросить фильтры» (глобально) | **Не используем** — сброс по колонке: «Выбрать все» + ОК (enum) или очистить текст + ОК; смена **search** сбрасывает column-filters. Поиск — отдельно (очистить поле поиска). |
| Глобальный search | При **изменении** `search` column-filters **сбрасываются** (новый контекст выборки). |

## Поведение MVP (функциональные требования)

### Общая цепочка данных

```
API (search) → rows в памяти → column filters (AND) → sort → отображение / Excel
```

- Глобальный `search` по-прежнему уходит на backend и **перезагружает** список.
- Column-filters применяются **поверх** загруженного набора.
- Между колонками логика **AND** (строка должна удовлетворять всем активным фильтрам).
- Сортировка применяется к **отфильтрованному** набору.

### UI заголовка колонки

- В каждом `th` (кроме `actions`): подпись, индикатор сортировки (как сейчас), **иконка/кнопка фильтра**.
- Клик по фильтру открывает выпадающее меню; клик по области сортировки — сортировка (клики не конфликтуют).
- Активный фильтр на колонке визуально выделен (например, заливка иконки accent).
- Сброс column-filter по колонке: enum — «Выбрать все» + **ОК**; text — очистить поле + **ОК**. Смена глобального **search** сбрасывает все column-filters.

### Типы фильтров по колонке

В `columnDefs` задаётся `filter`:

| `filter` | Колонки каталога ИС (пример) | Поведение |
|----------|------------------------------|-----------|
| `text` | код, наименование, полное наименование, вендор, описание, примечание… | Поле ввода «Содержит…»; пустое поле = фильтр выключен. Сравнение по **отображаемому** значению (`cellValue`), регистронезависимо. |
| `enum` | статус, тип хостинга, владелец, родитель… | Чекбоксы distinct (каскад). **ОК** с нулём галочек → 0 строк (`mode: none`); все галочки → фильтр колонки снят; часть → `mode: subset`. «Выбрать все» / «Снять все» — только в черновике до **ОК**. |
| `bool` | `external_system` | Как enum: «Да» / «Нет». |

Даты в каталоге ИС в текущих колонках нет; тип `date` (диапазон) зарезервировать в API composable для других реестров, в пилоте не обязателен.

### Значение для сравнения

- Для фильтрации и distinct использовать **то же**, что показывает `cellValue(row, key)` (например `external_system` → «Да»/«Нет», пустые → «(пусто)» в enum-списке).
- Колонка `actions` не фильтруется.

### Сортировка

- Клик по заголовку сортирует **отфильтрованный** набор; повторный клик переключает `asc` → `desc`.
- Для сравнения берётся **исходное** значение строки (`row[sortField || key]`), а не отформатированное для показа (`cellValue`): даты в формате `ДД.ММ.ГГГГ` при строковом сравнении дают неверный порядок (`01.02.2025` раньше `31.01.2025`).
- Тип сравнения задаётся в `columnDefs` полем `sortType`: `text` (по умолчанию), `number`, `date`, `datetime`. Для колонок с датой/временем `sortType` **обязателен**.
- Пустые значения (`null`, `''`, `'—'`) всегда оказываются **в конце** списка — и при `asc`, и при `desc`.
- При равных значениях сохраняется исходный порядок строк (стабильная сортировка).
- Реализация: `src/utils/tableSort.js` (`sortByColumn`, `compareSortValues`, `parseSortTimestamp`); используется в `useRegistryTable` и в таблице «Пользователи». Для нестандартных случаев `useRegistryTable` принимает опцию `sortValue(row, key, column)`.


- Префикс: `ARR_FILTER_COOKIE` из конфига или по умолчанию `ar_filters_`.
- Ключ: `ar_filters_<tableId>` → JSON, например:

```json
{
  "status": { "type": "enum", "mode": "subset", "selected": ["Эксплуатация", "Разработка"] },
  "name": { "type": "text", "contains": "портал" },
  "external_system": { "type": "bool", "mode": "subset", "selected": ["Да"] }
}
```

- Запись в cookie — **только после ОК** в меню фильтра (не при каждом символе в text).
- Невалидные ключи (колонка удалена из defs) игнировать.

### Экспорт в Excel

- На всех экранах rollout: **клиентская** сборка `.xlsx` (`exportTableToExcel`) из строк после **search + column filters + sort**.
- Колонки: **видимые** (`visibleCols`), без `actions`; заголовки — `label`, ячейки — `cellValue`.
- Серверный `?excel=true` для этих экранов **заменяется** на клиентский экспорт (как в каталоге ИС).

### Пустой результат

- Таблица без строк + текст «Нет записей» (как сейчас).
- Экспорт при 0 строк — кнопка disabled или сообщение «Нет данных для выгрузки».

## Тест-план (ручной)

1. Открыть каталог ИС без `?search=` — убедиться, что таблица загружена.
2. Фильтр `status` — выбрать 1–2 статуса; строки сужаются; иконка активна.
3. Добавить фильтр `name` «содержит» подстроку — пересечение условий.
4. Сброс фильтра колонки (enum «Выбрать все» + ОК) — полный список в рамках текущего search.
5. F5 — фильтры восстановились из cookie.
6. Смена глобального search — column-filters **сброшены**, новая выборка с API.
7. Скрыть колонку через «Вид» — экспорт без неё; фильтр по скрытой колонке может оставаться активным (допустимо) или сбрасываться при скрытии — **зафиксировать при реализации:** рекомендация — фильтр по скрытой колонке продолжает действовать, пока пользователь не сбросит (как в Excel).
8. Экспорт Excel — число строк = числу в таблице; колонки = видимым.
9. Сортировка по колонке с активным фильтром — порядок среди отфильтрованных.
