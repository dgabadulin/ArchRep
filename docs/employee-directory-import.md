# Сервисная операция: полная синхронизация справочника сотрудников из CSV

**Статус:** реализуется  
**GitHub:** https://github.com/dgabadulin/ArchRep/issues/122  
**Экран:** `Настройки → Сервисные операции → Загрузка справочника сотрудников`  
**API:** `POST /api/service-operations/employees/import/validate`, `POST /api/service-operations/employees/import/apply`  
**БД:** `archrep.ar_employees`

---

## 1. Назначение

Массовая загрузка справочника сотрудников из CSV-файла с режимом **полной синхронизации**:

- сотрудник с найденным табельным номером обновляется;
- сотрудник с новым табельным номером создаётся;
- сотрудник, который есть в БД с непустым табельным номером, но отсутствует в файле, помечается `active = false` («уволен»);
- сотрудники с пустым табельным номером в БД не изменяются и не деактивируются;
- физического удаления записей нет: исторические ссылки на сотрудника сохраняются.

Операция ручная. Периодическое задание и автоматическая синхронизация с HR-системой в текущий объём не входят.

---

## 2. Входной файл

### 2.1. Формат

- CSV, кодировка **UTF-8** (BOM допускается).
- Разделитель — `,` или `;`; определяется автоматически по первой строке.
- Первая строка — **обязательные заголовки**.
- Допускаются пустые строки; они пропускаются.
- Поля с разделителем/переносом строки должны быть в кавычках; кавычки внутри поля экранируются `""`.
- Один файл — одна таблица сотрудников.

### 2.2. Заголовки

Обязательны все пять колонок. Порядок колонок произвольный.

| Заголовок | Поле БД | Обязательность |
|---|---|---|
| `Табельный номер` | `employee_number` | Да |
| `Сотрудник` | `full_name` | Да |
| `Служебный адрес электронной почты` | `email` | Да, колонка; значение может быть пустым |
| `Должность` | `position` | Да, колонка; значение может быть пустым |
| `Подразделение` | `department` | Да, колонка; значение может быть пустым |

Допускаются алиасы без учёта регистра и лишних пробелов:

- `employee_number`, `табельный номер`, `табельный №`;
- `full_name`, `фио`, `полное имя`, `сотрудник`;
- `email`, `e-mail`, `почта`, `служебный адрес электронной почты`;
- `position`, `должность`;
- `department`, `подразделение`.

Шаблон CSV (первая строка заголовков):

```csv
Табельный номер;Сотрудник;Служебный адрес электронной почты;Должность;Подразделение
001234;Иванов Иван Иванович;ivanov@example.ru;Ведущий архитектор;Управление архитектуры
```

### 2.3. Значения

- `employee_number` — текст, ведущие нули сохраняются; сравнивается после `trim` и приведения к нижнему регистру.
- `full_name` — обязательное непустое значение.
- `email` — приводится к нижнему регистру; пустое значение очищает поле.
- `position`, `department` — пустое значение очищает поле.
- Полностью пустые строки пропускаются.
- Дубли `employee_number` в файле — ошибка для всех строк с этим номером.
- Одинаковые `email` в файле или `email`, занятый другим сотрудником, — ошибка строки.

## 3. Правила полной синхронизации

1. Импорт выполняется только по полному срезу справочника. Если файл содержит часть сотрудников (например, одно подразделение), операция не подходит.
2. Все сотрудники с непустым `employee_number`, отсутствующие в файле, переводятся в `active = false`.
3. Сотрудники из файла переводятся в `active = true` (в том числе ранее уволенные).
4. Сотрудники в БД с пустым `employee_number` не сопоставляются и не меняются.
5. Удаление записей запрещено.
6. При наличии **хотя бы одной ошибки строки** применение блокируется полностью: нельзя деактивировать людей по неполному/битому файлу.
7. Пустой файл, файл без заголовков, файл без валидных строк — ошибка.
8. Защита от случайного массового увольнения: если доля деактивируемых среди активных сотрудников с номерами превышает 50 %, требуется отдельное подтверждение (`allowLargeDeactivation = true`).
9. Перед применением обязателен dry-run (`validate`). UI показывает количество создаваемых, обновляемых, увольняемых и ошибочных строк.
10. `apply` требует:
    - `confirmDeactivate = true`, если есть деактивируемые;
    - `expectedDeactivateCount` из dry-run; если число изменилось — запрос отклоняется;
    - `allowLargeDeactivation = true`, если сработал порог массового увольнения.

## 4. Алгоритм

### 4.1. Validate (dry-run)

1. Разобрать CSV.
2. Проверить заголовки и строки.
3. Загрузить сотрудников из БД.
4. Сопоставить по `employee_number`.
5. Сформировать:
   - `would_create`;
   - `would_update`;
   - `would_reactivate`;
   - `would_deactivate`;
   - `errors`;
   - `untouched_without_number`;
   - списки строк и деактивируемых сотрудников.
6. Ничего не записывать в БД.

### 4.2. Apply

1. Повторить разбор и проверку.
2. Если `errors > 0` — вернуть 400, ничего не менять.
3. Проверить подтверждение деактивации и ожидаемое количество.
4. В одной транзакции:
   - создать новых;
   - обновить существующих, очистив пустые `email`/`position`/`department`, `active = true`;
   - деактивировать отсутствующих (`active = false`).
5. Зафиксировать транзакцию и вернуть итоговые счётчики и списки.

## 5. API

### `POST /api/service-operations/employees/import/validate`

Тело:

```json
{
  "fileBase64": "...",
  "filename": "employees.csv"
}
```

Ответ:

```json
{
  "summary": {
    "rows": 120,
    "would_create": 3,
    "would_update": 110,
    "would_reactivate": 2,
    "would_deactivate": 5,
    "errors": 0,
    "untouched_without_number": 7,
    "deactivate_ratio": 0.04,
    "requiresLargeDeactivationConfirm": false
  },
  "rows": [],
  "deactivate": []
}
```

### `POST /api/service-operations/employees/import/apply`

Тело дополняется:

```json
{
  "confirmDeactivate": true,
  "expectedDeactivateCount": 5,
  "allowLargeDeactivation": false
}
```

Ответ — те же счётчики со статусом `created`, `updated`, `reactivated`, `deactivated`.

### `GET /api/service-operations/employees/import/template`

Возвращает CSV-шаблон с заголовками и примером строки.

### Права

- `validate`, `template` — `import:execute`;
- `apply` — `import:execute` + `employee:write`.

## 7. Изменения БД

Новая dual-миграция `20261120130000_ar_employees_position_department`:

```sql
ALTER TABLE archrep.ar_employees
  ADD COLUMN IF NOT EXISTS position VARCHAR(255),
  ADD COLUMN IF NOT EXISTS department VARCHAR(512);
```

Дополнительно:

- удаляется уникальный индекс по первому слову ФИО (`ar_employees_first_word_lower_uidx`): ключом становится табельный номер, однофамильцы должны быть допустимы;
- создаётся обычный индекс по первому слову ФИО для поиска;
- SQL-скрипт завершается монотонным upsert-ом `archrep.ar_schema_info` на `20261120130000`;
- JS-миграция читает тот же SQL.

Существующие строки без табельного номера сохраняются и не деактивируются.

## 8. Критерии приёмки

- [ ] CSV с заголовками из §2.2 принимается без ручной конвертации.
- [ ] Заголовки можно менять местами; алиасы работают.
- [ ] Строки без табельного номера или ФИО дают ошибку.
- [ ] Дубли табельного номера в файле блокируют применение.
- [ ] Новый номер создаёт сотрудника.
- [ ] Существующий номер обновляет ФИО, email, должность, подразделение и ставит `active = true`.
- [ ] Пустые email/должность/подразделение очищают поля.
- [ ] Отсутствующий в полном файле сотрудник с номером получает `active = false`.
- [ ] Сотрудники без номера в БД не меняются.
- [ ] При ошибках строк apply не выполняется.
- [ ] Массовое увольнение требует отдельного подтверждения.
- [ ] Повторная загрузка того же файла не создаёт дублей.
- [ ] `npm test` зелёный; миграция маркера проходит `schemaMarker.test.js`.
