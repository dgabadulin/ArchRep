# Компонент архитектурной схемы на странице инкрементов (прикладное решение)

## Контекст

- **Страница:** прикладное решение (редактирование) → вкладка «Инкременты» → выбранный инкремент.
- **Данные:** список систем инкремента (`incrementSystems`: id, код, название, статус) и интеграций (`incrementRelations`: источник, приёмник, название, статус).
- **Цель:** выводить схему «системы — интеграции» и достраивать её по действиям пользователя (например, контекстное меню на системе → «Показать связи» → на схему добавляются все системы, связанные с выбранной).

## Варианты компонентов

### 1. **v-network-graph** (рекомендуется)

- **Описание:** Vue 3, SVG, граф из узлов и рёбер, реактивные данные.
- **Плюсы:**
  - Нативное событие **`node:contextmenu`** — правый клик по узлу, можно показать своё контекстное меню и отключить браузерное через `event.preventDefault()`.
  - Подходит под модель «системы = узлы, интеграции = рёбра».
  - Раскладка: встроенные SimpleLayout, GridLayout или **d3-force** (force-directed) при установке `d3-force`.
  - Pan/zoom, перетаскивание узлов, масштабирование объектов при зуме.
- **Минусы:** нужна отдельная реализация контекстного меню (позиционированный div по координатам события) и логики «Показать связи» (добавление узлов/рёбер в реактивные `nodes`/`edges`).
- **Установка:** `npm install v-network-graph` (при желании `d3-force` для авто-раскладки).
- **Документация:** [v-network-graph](https://dash14.github.io/v-network-graph/), [Events](https://dash14.github.io/v-network-graph/reference/events.html) (в т.ч. `node:contextmenu`).

---

### 2. **Vue Flow** (`@vue-flow/core`)

- **Описание:** Vue 3, flowchart-ориентированный граф (ноды с портами, связи между портами).
- **Плюсы:** богатый UI (Background, Minimap, Controls), Node Toolbar рядом с узлом, TypeScript.
- **Минусы:** заточен под потоковые/процессные схемы; контекстное меню по правому клику нужно делать самому (события есть, своего контекст-меню нет); тяжелее для простого «граф систем и интеграций».
- **Установка:** `npm install @vue-flow/core` (и при необходимости `@vue-flow/node-toolbar`).

---

### 3. **ECharts** (graph series)

- **Описание:** в проекте уже есть `public/echarts.min.js`; граф строится через опцию `series.type: 'graph'`.
- **Плюсы:** без лишних зависимостей во фронте, узлы и рёбра, события клика по узлу/ребру.
- **Минусы:** не Vue-компонент — нужна обёртка (ref + init/dispose), контекстное меню и достраивание схемы («Показать связи») полностью самописные.
- **Использование:** подключение скрипта или `import * as echarts from 'echarts'` при переносе в сборку Vite.

---

### 4. **Cytoscape.js**

- **Описание:** классическая JS-библиотека графов, без Vue из коробки.
- **Плюсы:** мощный API, расширения, в т.ч. для контекстного меню (cy-context-menus и др.).
- **Минусы:** обёртка во Vue и интеграция с реактивными данными инкремента — за разработчиком; размер бандла больше.

---

### 5. **Draw.io (diagrams.net) — встраиваемый редактор**

- **Описание:** полноценный веб-редактор диаграмм (mxGraph), встраивается через **iframe** — загружается `embed.diagrams.net`, обмен данными по **postMessage** (JSON-протокол).
- **Плюсы:**
  - Все визуальные требования «из коробки»: прямоугольники с закруглёнными углами, вложенные фигуры/блоки, произвольная раскраска вершин и рёбер, штрих линии (пунктир, точки и т.д.), богатые стили и библиотеки фигур.
  - Привычный UX редактирования: перетаскивание, масштаб, своё контекстное меню внутри редактора, сохранение в XML/PNG/SVG.
  - Схему можно **генерировать из данных**: собрать XML из `incrementSystems` и `incrementRelations` и отправить в iframe действием `load`; есть примеры и репозиторий [drawio-integration](https://github.com/jgraph/drawio-integration), [drawio-data-driven](https://github.com/jgraph/drawio-data-driven).
- **Минусы:**
  - Редактор в iframe — контекстное меню «Показать связи» нельзя встроить внутрь Draw.io без доработки самого редактора. Реализуют снаружи: кнопка/меню в нашей странице (Vue) по выбранной системе → пересборка XML с добавлением связанных систем/интеграций → отправка нового XML в iframe (`action: 'load'`). Выбор элемента «на схеме» можно синхронизировать через протокол (если поддерживается) или дублировать выбор в нашем списке систем.
  - Зависимость от внешнего сервиса (embed.diagrams.net) или развёртывание [drawio](https://github.com/jgraph/drawio) на своём сервере для офлайн/корпоративного использования.
  - Нет готового Vue-компонента — обёртка на Vue (ref на iframe, подписка на postMessage, вызовы `load`/`save`) делается вручную по [документации embed](https://www.drawio.com/doc/faq/embed-mode) и примерам из jgraph/drawio-integration.
- **Интеграция:** [Embed mode](https://www.drawio.com/doc/faq/embed-mode), [протокол](https://desk.draw.io/support/solutions/articles/16000042544), примеры: [drawio-integration examples](https://github.com/jgraph/drawio-integration/tree/main/examples/embed-mode).

## Требования: форма вершин, вложенные блоки, цвет, штрих рёбер

Сводка по возможностям компонентов.

| Требование | v-network-graph | Vue Flow | ECharts (graph) | Cytoscape.js | Draw.io (embed) |
|------------|-----------------|----------|------------------|--------------|------------------|
| **Вершины — прямоугольники с закруглёнными углами** | ✅ `type: "rect"`, `borderRadius`, `width`/`height` в конфиге узла | ✅ `style.borderRadius`, `width`/`height` у ноды | ✅ форма узла + `itemStyle.borderRadius` / rich-стили | ✅ `shape: 'roundrectangle'`, `border-radius` (3.29+) | ✅ Полноценный редактор: фигуры Rectangle, Rounded и т.д., настраиваемый радиус |
| **Внутри вершины — прямоугольники с функциями** | ⚠️ Слот `override-node-label`: свой Vue/HTML (несколько блоков). Форма узла одна, «вложенные прямоугольники» — через контент слота | ✅ **Лучше всего:** кастомный компонент ноды или вложенные ноды (nested nodes). Любая разметка: блоки, списки функций | ✅ Rich-подписи: `label.formatter` + `rich` — несколько «боксов» с фоном/рамкой внутри подписи узла. Не отдельные геометрические узлы | ⚠️ Обычно через расширение (напр. node-html-label) или кастомный label; возможны вложенные блоки в HTML | ✅ Вложенные фигуры, комбинированные фигуры, произвольная компоновка блоков внутри вершины |
| **Цвет вершин и рёбер** | ✅ Цвет узла: `normal.fill`, `normal.stroke` и т.д.; рёбра: `edge.normal.stroke` и по состояниям | ✅ Узел: `style.backgroundColor`, `borderColor`; ребро: `style.stroke`, CSS-переменные | ✅ Узел: `itemStyle`; ребро: `lineStyle.color` | ✅ Узел: `background-color`, `border-color`; ребро: `line-color`, стили по селекторам | ✅ Полная палитра заливки/обводки для фигур и линий |
| **Штрих линии рёбер (пунктир и т.д.)** | ✅ `edge.normal.dasharray` (напр. `"6"` для пунктира) | ✅ `style.strokeDasharray` у ребра (напр. `'5,5'`) | ✅ `lineStyle.type: 'dashed'` / `'dotted'` | ✅ Свойства линии (в т.ч. dash) в стилях рёбер | ✅ Стиль линии: сплошная, пунктир, точки и т.д. в панели свойств |

### Детали по «прямоугольникам с функциями» внутри вершины

- **Vue Flow** — максимальная гибкость: кастомный компонент ноды с любой вёрсткой (несколько блоков, списки функций) или встроенные **nested nodes** (дочерние ноды внутри родительской). Идеально, если «функции» — это отдельные визуальные блоки или подузлы.
- **v-network-graph** — один прямоугольник узла (rect + borderRadius), содержимое задаётся слотом `override-node-label`. Внутри слота можно рендерить несколько div’ов/прямоугольников (функции), но они ведут себя как часть подписи/контента, а не как отдельные перетаскиваемые узлы.
- **ECharts** — несколько «боксов» внутри подписи узла через **rich text** (`label.formatter` + `rich`): разный фон, отступы, скругления. Подходит для текстовых блоков с функциями, без интерактивных подузлов.
- **Cytoscape.js** — кастомный контент в узле обычно через расширения (HTML в лейбле) или сложную стилизацию; вложенные прямоугольники возможны, но требуют больше ручной работы.

**Draw.io (embed)** — полноценный редактор диаграмм: вершины и рёбра — это фигуры и соединители с полным набором стилей (прямоугольники с закруглением, вложенные блоки, цвет, штрих линий). «Показать связи» реализуется снаружи iframe: по кнопке/меню в нашем UI пересобираем XML схемы с добавлением связанных систем и отправляем в редактор через `action: 'load'`. Готового Vue-компонента нет — нужна обёртка (iframe + postMessage).

Если приоритет — **богатая разметка внутри вершины** (прямоугольники с функциями как отдельные блоки или подузлы), сильнее всего подходит **Vue Flow**. Если достаточно одного скруглённого прямоугольника и текстовых/блочных подписей — подходят **v-network-graph** и **ECharts**. Если нужен **максимально привычный редактор диаграмм** с полной свободой оформления и готовностью пользователей к Draw.io — подходит **встраивание Draw.io**.

## Рекомендация

**Оптимальный вариант — v-network-graph:**

1. Поддержка **контекстного меню из коробки** через `node:contextmenu` и свой UI меню.
2. Модель данных совпадает с нашими сущностями: узлы = системы, рёбра = интеграции (source → target).
3. Удобно достраивать схему: по действию «Показать связи» для выбранной системы добавляем в граф связанные системы и рёбра (из `incrementRelations` и при необходимости подгрузка данных), обновляя реактивные `nodes`/`edges`.
4. Один пакет под Vue 3, без лишней сложности flowcharts (Vue Flow) и без оборачивания ECharts/Cytoscape.

## Реализация контекстного меню и «Показать связи»

- В обработчике `node:contextmenu`:
  - `event.preventDefault()`.
  - Показать свой компонент/div меню в позиции `(event.clientX, event.clientY)` с пунктом «Показать связи».
- По клику «Показать связи»:
  - По выбранному `node` (id = система) найти в `incrementRelations` все связи (from/to).
  - Собрать множество систем, которых ещё нет в текущем наборе узлов графа.
  - Добавить недостающие узлы (системы) и рёбра (интеграции) в данные графа; при использовании d3-force новые узлы можно добавить с координатами по умолчанию и дать симуляции пересчитаться.

При необходимости можно вынести список пунктов контекстного меню в конфиг (например, «Показать связи», «Скрыть связи», «Центрировать на узле») и вызывать одну и ту же логику достройки/обновления графа.
