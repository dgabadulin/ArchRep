# Главная страница: объём каталога (KPI + аккордеон)

**Статус:** реализовано (см. `backend/homeDashboard.js`, `GET /api/dashboard/home-stats`, миграция `archrep_issue34_home_dashboard.sql`).  
**Задача:** [issue-34 в репозитории](./issue-34-home-dashboard-catalog-metrics.md) · [GitHub #34](https://github.com/dgabadulin/ArchRep/issues/34)  
**UI:** `frontend-v3/src/views/HomeView.vue`

---

## 1. Приоритет

На главной важнее **объём каталога** (сколько объектов учтено), а не оценка «наполненности карточек» по обязательным полям. Показатели качества заполнения на KPI-плитках **не обязательны** в первой версии; при необходимости их можно добавить позже (например тонкий индикатор относительно порога).

**Обновление данных:** отдельного автообновления не требуется — пользователь обновляет страницу (F5). При желании на бэкенде допускается короткий кэш агрегатов; это не меняет модель «без polling».

## 2. Компоновка (сочетание вариантов B и D)

| Зона          | Вариант          | Содержание                                                                                                                                                          |
| ------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Верх страницы | **D — сводка**   | KPI-плитки по конфигу из системного параметра (см. п. 3–4).                                                                                                         |
| Визуал плиток | **B — карточки** | Иконка, **крупное число** (основной счётчик), заголовок/шаблон сверху или рядом по макету, **нижняя строка мельче** (второй счётчик + шаблон), оформление карточки. |
| Ниже / рядом  | **Аккордеон**    | Все **остальные** показатели объёма по типам сущностей метамодели (см. п. 7). Текущие переходы по разделам (плитки меню) сохраняются; блок метрик **дополняет** их. |

Размещение: **справа от существующих плиток навигации** на широкой сетке или **под** вводным блоком — уточняется при вёрстке; на узких экранах KPI и аккордеон **стеком**.

---

## 3. Содержание KPI-плиток (зафиксированные правила подсчёта)

Конфигурация **текстов и имён функций** задаётся параметром (п. 4). Ниже — **бизнес-смысл чисел** (реализуется внутри функций `archrep`).

### 3.1. Информационные системы

| Показатель                | Правило                                                                                                                                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Первая цифра (крупно)** | `COUNT(*)` по **`archrep.ar_systems`** — все записи в таблице систем.                                                                                                                                                                                                                                              |
| **Вторая цифра (внизу)**  | Записи с **заполненным родителем**: `parent_ar_systems_id IS NOT NULL` (в схеме ИС используется **`parent_ar_systems_id`**, не абстрактное `parent_id`). По возможности исключить некорректную самоссылку: `parent_ar_systems_id <> id` (как в логике модулей, см. `archrep_issue32_system_module_relations.sql`). |

**Подпись (пример):** «Информационные системы: …» + крупно всего; внизу «в т.ч. **N** подсистем и модулей» (точные шаблоны — в JSON параметра).

### 3.2. Интеграционные потоки

| Показатель       | Правило                                                                          |
| ---------------- | -------------------------------------------------------------------------------- |
| **Первая цифра** | `COUNT(*)` по **`archrep.ar_integration_flows`**.                                |
| **Вторая цифра** | Не требуется; в конфиге плитки `footerFn` / `footerTpl` можно опустить (`null`). |

### 3.3. Технологические компоненты

| Показатель       | Правило                                                                     |
| ---------------- | --------------------------------------------------------------------------- |
| **Первая цифра** | `COUNT(*)` по **`archrep.ar_technologies`**.                                |
| **Вторая цифра** | **Иностранные:** `domestic_flag IS NULL` (флаг отечественного ПО не задан). |

**Подпись (пример):** внизу «в т.ч. **M** иностранных».

### 3.4. Архитектурный долг

| Показатель                           | Правило                                                                                                                                                                    |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Первая цифра**                     | `COUNT(*)` по **`archrep.ar_gaps`** — все записи реестра.                                                                                                                  |
| **Вторая цифра («в т.ч. закрытые»)** | Записи с **заполненной датой закрытия**: **`resolved_date IS NOT NULL`** (колонка **`resolved_date`** в `ar_gaps`, см. `DB/schema/archrep_issue23_architecture_debt.sql`). |

*Примечание:* в обсуждении фигурировала фраза «дата закрытия пусто»; для подписи **«закрытые»** зафиксировано противоположное: закрыто = дата **указана** (`IS NOT NULL`). Показ **незакрытых** (`resolved_date IS NULL`) — отдельное требование, не эта плитка.

### 3.5. Дубли с аккордеоном

KPI-плитки **не дублировать** в аккордеоне теми же цифрами. Типы сущностей, попавшие в KPI, из списка аккордеона исключаются (или настраивается явным списком кодов).

## 4. Системный параметр: JSON-конфиг плиток

Вместо многострочного текстового формата используется **один параметр** (тип JSON или текст с JSON), например **`ARR_HOME_KPI_TILES`**.

### 4.1. Структура элемента массива

Каждый элемент описывает **одну плитку**:

| Поле        | Назначение                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------- |
| `titleTpl`  | Шаблон строки с основным числом (плейсхолдеры на усмотрение реализации, напр. `{total}`).                   |
| `countFn`   | Имя функции **`archrep`** для **первой цифры**: `RETURNS bigint`, без параметров (или с дефолтами).         |
| `footerTpl` | Шаблон **нижней** строки (напр. `в т.ч. {n} подсистем и модулей`) или `null`, если второй счётчик не нужен. |
| `footerFn`  | Имя функции для **второй цифры** или `null`.                                                                |
| `icon`      | Опционально: ключ иконки для фронта (согласовать с `icons.js` / Lucide).                                    |

Имена функций должны проходить **whitelist** на бэкенде: выполняется только `SELECT schema.fn()` для разрешённых `fn`.

### 4.2. Пример JSON (черновик)

```json
[
  {
    "titleTpl": "Информационные системы:",
    "countFn": "archrep.dashboard_home_systems_total",
    "footerTpl": "в т.ч. {n} подсистем и модулей",
    "footerFn": "archrep.dashboard_home_systems_with_parent"
  },
  {
    "titleTpl": "Интеграционные потоки:",
    "countFn": "archrep.dashboard_home_integration_flows",
    "footerTpl": null,
    "footerFn": null
  },
  {
    "titleTpl": "Технологические компоненты:",
    "countFn": "archrep.dashboard_home_technologies_total",
    "footerTpl": "в т.ч. {n} иностранных",
    "footerFn": "archrep.dashboard_home_technologies_foreign_null_flag"
  },
  {
    "titleTpl": "Архитектурные отклонения:",
    "countFn": "archrep.dashboard_home_gaps_total",
    "footerTpl": "в т.ч. {n} закрытых",
    "footerFn": "archrep.dashboard_home_gaps_closed"
  }
]
```

Имена функций в примере — проектные; финальные сигнатуры задаются в миграции.

### 4.3. Поток на бэкенде

1. Прочитать параметр `ARR_HOME_KPI_TILES`, распарсить JSON.  
2. Для каждой плитки: вызвать `countFn`, при наличии — `footerFn`.  
3. Подставить значения в `titleTpl` / `footerTpl`.  
4. Отдать фронту готовые строки и числа (или структурированно — на усмотрение API).

## 5. Функции подсчёта в БД

- Реализуются как **отдельные функции** в схеме **`archrep`**, по одной ответственности на метрику (см. п. 3).  
- Внутри — только допустимые `COUNT`/`SELECT` по согласованным таблицам; без динамического SQL из параметра.  
- Желательно пометить **`STABLE`**, если нет побочных эффектов.

**Безопасность:** конфиг плиток ссылается на функции по имени; бэкенд не исполняет произвольный SQL из параметра, только вызовы из whitelist.

---

## 6. Аккордеон «всё остальное»

- Строки строятся по **`archrep.ar_metamodel_entity_types`**, исключая коды **`system`**, **`technology`**, **`gap`** (уже в KPI).  
- Для каждой строки: подпись **`name`**, **`code`**, одно число объёма.  
- Подсчёт: whitelist **`ACCORDION_COUNT_SQL`** в `backend/homeDashboard.js` (безопасные `SELECT COUNT(*) …` по таблице типа). Типы без записи в whitelist в аккордеон **не** попадают (до явного расширения списка).

### 6.1. Новый тип сущности (чеклист для разработчика)

При добавлении полноценного реестра (см. [adding-new-entity-type.md](./adding-new-entity-type.md) §4.6):

1. Убедиться, что в **`ar_metamodel_entity_types`** есть строка с **`code`**, совпадающим с ключом в коде.
2. В **`backend/homeDashboard.js`** → **`ACCORDION_COUNT_SQL`**:  
   `'<code>': 'SELECT COUNT(*)::bigint AS c FROM archrep.<table>'`  
   (только статический SQL, без подстановки из параметров).
3. Перезапустить API; обновить главную — в аккордеоне должна появиться строка с **`label`** из метамодели.

KPI-плитка для нового типа — отдельный, более тяжёлый путь (§4–5); для большинства реестров достаточно аккордеона.

**Текущие ключи `ACCORDION_COUNT_SQL`:** `organization_unit`, `actor`, `business_service`, `business_function`, `principle`, `web_resource`, `domain`.

## 7. API

**Реализовано:** `GET /api/dashboard/home-stats`.

Ответ:

```json
{
  "kpiTiles": [
    {
      "title": "Информационные системы",
      "primary": 42,
      "footer": "в т.ч. 10 подсистем и модулей",
      "icon": "desktop",
      "error": false
    }
  ],
  "accordion": [
    { "entityTypeCode": "organization_unit", "label": "…", "count": 0 }
  ]
}
```

При ошибке вызова функции для плитки: `primary: null`, `error: true`, `footer: null`.

Либо сырьё для подстановки шаблонов на фронте — по решению реализации; принцип: **числа с бэка**, шаблоны из параметра.
