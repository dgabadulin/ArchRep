## 2. Выделение объектов

Механика опирается на штатные средства `v-network-graph` 0.9.x:

- `v-model:selected-nodes` / `v-model:selected-edges` — наборы выбранных объектов;
- `selectable: 1` у узлов и связей — лимит одновременного выбора;
- события `node:click`, `edge:click`, `node:contextmenu`, `edge:contextmenu` — выделение и на ЛКМ, и на ПКМ
  (ПКМ у библиотеки выделение не меняет, поэтому `selectOnly()` вызывается вручную);
- клик по пустому полю снимает выделение (поведение библиотеки).

Дополнительно:

- **важно для конфига**: `node.selected` и `edge.selected` должны содержать полный набор полей стиля
  (`type/width/height/borderRadius` для узла, `width/color/dasharray/linecap/animate` для связи).
  Библиотека не мержит их с `normal`: если у выбранного узла нет `width/height`, геометрия рёбер
  получает `NaN` в `d` и **связи выбранного узла пропадают** (проверено headless-стендом с mock-графом);
- «чужой» набор очищается: выбрали узел — снимается выделение связи и наоборот;
- выделение сбрасывается, если объект исчез с графа (скрытие объекта/связи, свёртка модулей, новый граф) —
  `pruneSelection()` на изменение состава `nodes` / `edges`;
- встройка на формах (`variant="embed"`) получает то же выделение, но без палитры.

## 3. Палитра свойств

Левая колонка анализатора (ширина 320 px, сворачивается кнопкой «‹»).

### Блок «Настройки»

| Ключ | Значение |
|------|----------|
| Связи каскадно | Да / Нет (выпадающий список; недоступен, если граф построен не от одного объекта) |
| Показать легенду | Да / Нет (выпадающий список; легенда типов сущностей поверх графа) |
| Показать связи | Да / Нет (выпадающий список; панель типов связей выбранного объекта с чекбоксами) |
| Топология графа | выпадающий список существующих раскладок: Звезда, Кольцо, Расш. звезда, Иерархия, Полносвязная, Сетка |

Смена топологии уходит в родителя событием `layout` — так же, как работали прежние кнопки раскладок
(`AnalyticsView.onLayout` → `analyzerRef.applyLayout`).

### Панели поверх графа: легенда и «Связи»

Обе панели — плавающие окна с шапкой (название + крестик). Закрытие крестиком выставляет соответствующий
пункт панели настроек в «Нет».

- **Легенда** (слева снизу) — типы сущностей метамодели с иконкой узла.
- **Связи** (справа снизу) — типы связей выбранного узла: подпись из справочника типов связей, число рёбер
  и чекбокс. Чекбокс **глобально** скрывает/показывает все рёбра этого типа на графе; по умолчанию
  включены все типы. Список строится по полному набору рёбер узла, поэтому скрытый тип можно вернуть.
  Узлы, потерявшие все рёбра из-за фильтра, скрываются автоматически, кроме корня графа (`centerNodeId`)
  и текущего выбранного узла. Фильтр сохраняется при закрытии панели и сбрасывается при «Новый граф»
  (компонент графа пересоздаётся). Если выбрана связь, а не узел, панель показывает подсказку.

### Блок «Свойства»

- пусто → подсказка «Выберите узел или связь на графе»;
- узел → `fetchEntity(тип, id)` (тот же запрос, что делала модалка ПКМ → «Просмотр»);
- связь → строка реестра `ar_metamodel_relations` из уже загруженного массива `relations` (по `relationId`);
- пучок интеграционных потоков → свойства ребра + кнопка «Список потоков (N)…» (та же модалка, что в ПКМ);
- значения только для чтения, под таблицей — подпись «Данные только для просмотра (без изменения)».

Формат значений: пусто → «—», boolean → Да/Нет, ISO-дата/время → `дд.мм.гггг чч:мм`,
объекты и массивы (`payload`, `memberRelationIds`) → JSON в моно-ширине с прокруткой.

Порядок строк: сначала смысловые поля (`name`, `code`, `status`, `owner`, `parent_name`, `description`, …),
затем остальные по алфавиту подписи. Подписи частых полей — словарь `FIELD_LABELS`, остальные ключи — как в БД.

## 4. Разрешение идентификаторов (клиентское, без бэкенда)

Правило `resolveIdentifier()` (`utils/analyzerProperties.js`), по приоритету:

1. **Парное поле в том же ответе.** Для ключа `…_id` ищется человекочитаемое поле-подпись:
   явная карта (`FK_LABEL_FIELDS`), затем вывод из ключа (`status_id` → `status`, `ar_domains_id` → `domain_name`).
   Пример: `ar_system_statuses_id: 3` + `status: "В эксплуатации"` → «В эксплуатации (id 3)».
2. **Объект графа.** Если для FK известен тип (`FK_ENTITY_TYPES`: `vendor_ar_partners_id` → `partner`) и узел
   присутствует на схеме, берётся его `name` (display_name) → «ООО «Ромашка» (id 12)».
3. **Иначе** — исходное значение (как в БД).

Что покрывается «бесплатно» (подписи уже приходят в detail-эндпоинтах): ИС и модули (`status`, `vendor`,
`supplier`, `supporter`, `owner`, `hosting`, `parent_name`, лиды), арх. долг, веб-ресурсы, домены,
сертификаты, функции ИС, ADRA/ADRP, орг. единицы, акторы, бизнес-сервисы/функции, сотрудники, инфраструктура.

Чего нет: справочники, которые не являются объектами графа (например, статус технологии или принципа,
если эндпоинт не вернул `*_name`) — показываются числовым id. Систематическое разрешение таких ссылок
(эндпоинт подписей по паре «тип+id», аналог `backend/relationLabels.js`) — отдельная задача.

## 5. Что не менялось

- Контекстное меню ПКМ и модалка «Просмотр» (сырой JSON) — остаются, в том числе для встройки на формах.
- Экспорт SVG/PNG, легенда, каскад, скрытие объектов, свёртка/развёртывание модулей, раскладки.
- API и БД: изменений нет, используются существующие эндпоинты.

## 6. Проверка (ручной чек-лист)

1. Построить граф от одной ИС → левая палитра показывает блоки «Настройки» и «Свойства».
2. ЛКМ по узлу — рамка; в «Свойствах» поля объекта, id разрешены (статус, владелец, вендор).
3. ПКМ по узлу — узел тоже выделяется, меню работает как раньше.
4. ЛКМ по связи — связь красная, рамка узла снята; в «Свойствах» поля связи, концы — наименованиями.
5. ПКМ по связи → «Просмотр» — прежняя модалка с JSON.
6. Пучок потоков (свёрнутые интеграционные потоки) — свойства ребра + кнопка «Список потоков (N)…».
7. ПКМ → «Скрыть объект» при выделенном узле — выделение снимается, палитра возвращается в пустое состояние.
8. «Связи каскадно», «Показать легенду», «Топология графа» из палитры — работают; топология применяется к графу.
9. Вкладка «Связи» на форме ИС/арх.долга — палитры нет, прежний тулбар/экспорт не сломан, выделение работает.
10. `npm run check:sfc`, `npm run build:v3`, `npm test` — без ошибок.
